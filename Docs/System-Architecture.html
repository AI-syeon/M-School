MagicCampus 시스템 구조

Unity 위에서 도는 상호작용 게임 런타임의 코드 구조. 2026-11-05 기준 master(d4399d4, 리팩토링 3단계 완료) 코드를 읽어 정리했다. 규칙과 상태는 Unity를 모르는 순수 C#(Domain)에 두고, Unity·파일·화면은 포트 뒤의 어댑터가 맡는다.

어셈블리 구조 화살표 = 참조(의존) 방향

의존은 한 방향이다. Contracts가 맨 아래에서 모두가 공유하는 경계 타입을 정의하고, Domain·UnityAdapters·Presentation은 서로를 참조하지 않는다. 셋을 묶는 곳은 Bootstrap 한 곳뿐이다.

Domain은 IMapPort·IFileGenerationStore 같은 포트로만 바깥을 부른다. 구현체(MapAdapter, FileGenerationStore…)는 UnityAdapters에 있고 Bootstrap이 끼워 넣는다. 3단계 리팩토링에서 Contracts는 1,352줄 → 616줄로 줄었다(경계를 넘지 않는 타입은 Domain으로 이동).

Domain 모듈 카드를 누르면 파일과 핵심 타입이 펼쳐진다

Domain 안쪽은 폴더별 모듈이다. 폴더 이름이 그대로 네임스페이스 구획이다. 막대는 Domain 전체(9,245줄) 대비 크기.

서비스 의존 그래프 노드를 누르면 의존 관계가 강조된다

FirstConnectionRuntime의 생성자가 객체를 만들고 이어 붙이는 순서(약 190~290행)를 그대로 옮긴 그림이다. 화살표는 "A가 B를 받아서 쓴다"이다.

■ 파랑 = 선택한 노드가 쓰는 것 · ■ 빨강 = 선택한 노드를 쓰는 것. 조립 루트(FirstConnectionRuntime)는 아래 모든 객체를 만들지만, 그림이 복잡해지지 않도록 직접 호출하는 응용 서비스 쪽만 선으로 그렸다.

프레임 루프 FirstConnectionRuntime.Step(dt)

게임은 매 프레임 한 번 Step을 부른다. 모든 비동기 작업은 핸들로 돌려주고, 완료 콜백은 다음 틱에 완료 큐(CompletionPump)가 순서대로 배달한다. 서비스마다 일시정지 채널(Calendar·Ambient·Player·World·Scene)을 스스로 확인해 멈춘다.

Pump.AdvanceTick이전 틱의 완료 콜백 배달
Ticks.AdvanceScene 정지 중이면 0초만 진행 → wait 정지
WatchdogStarting·Loading이 시간 초과면 취소
Disk.Tick파일 세대 저장소 비동기 처리
Maps.Tick맵 로드·전환
Staging.Tick예약 합류 연출 진행
Moves.Tick모든 이동(플레이어·NPC·연출) 한 곳에서
DialogueUi.Tick대화창·선택지
Runner.Tick이벤트 스크립트 진행 (틱당 즉시 명령 ≤ 64)
Clock.AdvancePhase == Ready일 때만. 시간은 상태 커밋으로 흐른다
Scheduler.TickReady일 때만. NPC 일정 이동

점선 칸은 RuntimePhase.Ready 이후에만 도는 단계. 시작·불러오기 중에는 게임 시간이 가지 않는다.

상태와 커밋 3단계 리팩토링으로 도달한 구조

예전에는 상태가 JSON 트리였고 변경마다 계획·참가자·스키마 검사를 거쳤다. 지금은 불변 GameState를 순수 함수로 바꿔 참조 하나를 교체한다. 잘못된 상태는 타입이 만들지 못하게 막고, 스키마 검사는 불러오기·저장 두 경계에서만 한다.

GameState (불변)

GameState
├─ Clock         ClockState          시각·하루 경계·day jobs
├─ World         WorldState          플레이어 위치, NPC 위치
├─ Progress      Progress
│   ├─ Flags         FlagTable      bool/int 변수
│   ├─ Completed     KeySet         완료 id
│   ├─ RewardLedger  KeySet         보상 받은 키

├─ Known         Knowledge          증거·주문·사건 (읽기 전용)
└─ Preserved     PreservedFields    규칙 없는 필드, 불투명 DataNode
               저장 때 그대로 되돌려 쓴다

IsConsumed 한 함수가 중복 보상 규칙을 담당한다(예전엔 6곳). SaveNumber는 저장 바이트의 정수/실수 표기를 보존한다.

이벤트 실행 EventRunner

이벤트는 카탈로그에 컴파일된 스크립트(CompiledEvent)다. 장면(scene) 이벤트는 자원을 전부 임대하고, 입장 상태를 저장한 뒤에야 스크립트를 시작한다. 성공은 CommitEvent 한 번이고, 어느 단계에서든 실패하면 입장 상태로 되돌린다.

① 시작 → 입장 (장면 이벤트만)

entry.project

② 스크립트 → 커밋 → 종료

call

컴파일된 호출 실행: move · perform · choice · wait · fork. 비동기는 핸들로 대기

조건 재검사

최신 리비전에서 ConditionEvaluator 다시 평가

commit

EventRules.Complete 한 함수가 플래그·완료·보상장부·크라운·시간비용·위치·예약행을 한꺼번에 쓴다

done

정지·임대 해제. 커밋 뒤 저장 실패는 메모리 성공을 취소하지 않고 별도 결과로 드러남

③ 실패·취소·시간 초과

abort

자식 작업 취소, 전부 종료될 때까지 대기

cleanup

소유한 표시(대화창 등) 닫기

restore

진입 맵·상태 복원 (장면만). 안전 경계 추적 재개(Renew)

release

정지, 마지막으로 임대 해제. 이미 일어난 커밋은 되돌리지 않음

방 활동(room activity)은 월드 자원·입장 저장·복원이 없고 등록된 작업만 기다린다. 모든 단계는 Trace 콜백으로 EventTraceEntry(tick, seq, revision, phase)를 내보내 테스트와 진단에 쓰인다.
