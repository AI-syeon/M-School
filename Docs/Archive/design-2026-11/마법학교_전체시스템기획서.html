전체 구조와 공통 실행 계약

2026-11-06 개정. 근거는 Assets/MagicCampus/Core/*.cs, Game/*.cs, Tests/Core/Program.cs다. Task1~5는 이 구현을 설명하며, 후속 Task의 새 기능은 미구현 계획으로 구분한다. 이전 기반의 포트·서비스·저장 스키마를 복원하는 작업으로 해석하지 않는다.

Core assembly는 noEngineReferences=true이며 JSON과 파일 IO를 직접 사용한다. Contracts, StateStore, Bootstrap 서비스 그래프, 별도 UnityAdapters 계층을 새로 만들지 않는다. Unity 6000.6.3f1, Input System 1.19.0, Newtonsoft.Json 3.2.2는 현재 프로젝트 파일의 값이다.

한 프레임

GameRoot는 입력을 처리한다. 메뉴가 열려 있으면 Game.Update를 호출하지 않는다. 메뉴가 아니면 dt를 최대 0.1초로 제한하고 한 번 호출한다. 초대/일지/침대 확인 패널에서는 플레이어 입력만 0이며, NPC와 시계는 계속 간다.

Game.Update는 Event가 있으면 EventRun.Update만 실행하고 반환한다. 따라서 이벤트 중 평상 NPC 일정·일반 플레이어 이동·자연 시간은 정지하며 이벤트 이동과 대화는 진행한다. Event가 없으면 플레이어 이동 → NPC 경로 이동 → 초 누적을 게임분으로 전환 → Schedule.Run → 02:00 검사 순서다. 별도 완료 큐·revision·정지 채널·비동기 Handle은 없다.

권위 상태와 저장

GameState의 Day, Minute, Player, Wallet, Flags, Completed, Appointments가 영속 상태다. Player는 실제 Actor이고 UI Transform은 권위가 아니다. NPC Actor 목록은 Game이 가지며 저장하지 않는다. Path, Speed, Moving, EventRun, Dialogue, Hidden, 메뉴, 입력, 초 잔여량은 영속하지 않는다.

State는 가변 객체다. 완료 시 효과를 순차 적용하고 Completed에 eventId를 추가한 뒤 비용을 가산하고 약속을 제거한다. 현재 코드는 범용 원자 트랜잭션이나 예외 롤백을 보장하지 않는다. 유효한 콘텐츠를 사전 시험하는 전제이며, 새 효과는 검증 후 쓰는 구체적 메서드로 추가한다. 잘못된 효과 중간 예외가 부분 변경을 남길 가능성은 Task5의 확인 항목이다.

시간과 하루 종료

Day는 0부터, UI는 Day+1이다. Minute는 해당 생활일의 07:00=420에서 시작하고 자정을 지나도 1440 이상으로 이어진다. 02:00=1560에 기절한다. 자연 시간은 1초=1게임분이다. 이벤트의 CostMinutes는 성공할 때 한 번 더한다. 현재 이벤트 비용으로 1560을 넘겨도 다음 평상 Update에서 하루 종료를 검사한다.

침대 반경 1 이내의 수면 확인은 EndDay(Slept), 시간 초과는 EndDay(PassedOut)를 부른다. EndDay는 이벤트 중 거부한다. Day++ → Minute=420 → 초 잔여량=0 → 침대로 플레이어 배치 → 현재 일정으로 NPC 배치 → SaveFile.Write 순서다. 성공 이벤트·수락·취소·종료 자체는 저장하지 않는다. 그날 미저장 진행은 강제 종료/불러오기 때 마지막 하루 저장으로 돌아간다.

그래픽과 좌표

논리 1칸은 32×32 픽셀 타일이다. 좌표는 double, 셀은 floor(x), floor(y), 셀 중심은 +0.5, 월드 y는 위로 증가한다. 플레이어 속도는 초당 3칸, 충돌 반경은 0.2칸이다. 일반 이동은 축별 검사이며 sweep 충돌은 구현되지 않았다. NPC/이벤트 이동은 4방향 BFS와 경로 추종을 쓴다. 포털 셀에 새로 진입할 때만 전이한다.

현재 Stage5Art/runtime-manifest.json은 pixelsPerUnit=16이고 WorldView 기본값도 16이다. 이는 32×32 제작 기준과의 기존 불일치다. Task6-6/15-7에서 32px 원본·manifest·표시 검사를 함께 맞추며, 숫자만 바꾸어 자산 변환 완료로 보지 않는다.

이후 확장 원칙

새 규칙은 Core 안의 작은 구체 클래스/메서드, 데이터 정의는 Content, 영속 값은 GameState, 화면은 Game에 추가한다. Game이 호출 순서와 상태 변경을 통제한다. 공통 파일은 같은 단계라도 순서대로 수정한다. 분리된 규칙 파일과 시험만 독립 작업할 수 있다.

실시간 방은 Game.Event와 별도의 임시 RoomRun을 두는 후속 설계다. 한 프레임에서 전경 이벤트와 방 실시간 조작을 동시에 진행하지 않는다. 수면·기절은 RoomRun 정리 후 기존 EndDay 하나로 합류한다. 방 체크포인트는 세션 내 재시도용이며 디스크 자동 저장과 다르다.

후속 필드를 추가할 때 기본값, 로드 정규화, 구형 현재 저장 fixture 왕복을 함께 구현한다. 기존 v1/v2 전체 저장 예제는 이전 엔진 자료이며 현재 저장에 그대로 로드하거나 강제 보존하지 않는다. 버전·마이그레이션이 필요하면 현재 무버전 GameState를 최초 입력으로 지원한다.

systems/03-systems.md

시스템별 현재 실행 명세

콘텐츠

Content.Load는 runner-bundle.json과 staging-recipes.json을 읽는다. 런타임은 타입/스키마 컴파일을 하지 않는다. Tests/Core의 Problems가 배포 데이터의 참조·지원 호출·경로·recipe를 사전 확인한다. 새 콘텐츠를 추가하면 이 검사도 확장한다.

월드와 이동

Passable은 맵 경계와 blocked 셀을 검사한다. 플레이어는 반경 0.2칸으로 축별 이동한다. FindPath는 포털까지 포함한 4방향 BFS이며 Walk가 속도 예산으로 경로를 따라간다. 이벤트 move는 경로 소진과 destination.radius를 확인한 뒤에만 다음 대사로 넘어간다. NPC 간 충돌·동적 맵 재탐색·timeout·sweep은 없다. 도달 불가 WalkTo는 예외다.

상호작용과 약속

interact npc label range가 상호작용 범위를 정한다. 가장 가까운 NPC를 고른 뒤 그 NPC의 Appointments에 남아 있는 이벤트를 표시한다. Accept는 Offered를 Accepted로 바꾸며 재수락은 false다. GameRoot는 수락/시작/수락 후 시작을 제공한다. StartEvent 자체는 예약 존재나 Accepted 여부를 검사하지 않고 진행 이벤트·완료·when을 검사한다. 콘텐츠 작성자는 UI 경로와 Core 진입 가드의 차이를 인지한다.

전경 이벤트

Game.Event 하나가 전경 전체를 독점한다. EventRun 생성 시 모든 Actor를 복사한다. 첫 프레임은 Hidden 상태로 recipe.join을 배치하고 반환한다. 다음 프레임에 Hidden=false로 바꾸고 순차 실행한다. say는 확인, choice는 선택한 fork 삽입, move는 도착을 기다린다. 성공 시 set/currency.add → eventId 완료 → 비용 → 약속 제거 순서다.

취소는 Actor 복사본을 되돌리고 대화/Hidden을 닫은 뒤 EndEvent로 NPC의 현시각 일정 경로를 다시 만든다. 약속과 완료 전 상태는 유지한다. 이 복원은 메모리 동작이며 디스크 진입 저장이 아니다. 실행 예외는 GameRoot.Error에 표시되며 자동 CancelEvent/롤백이 보장되지 않는다.

시간·일정·정지

평상시 시계와 NPC가 진행한다. 이벤트 중 자연 시간과 평상 일정은 정지한다. 메뉴는 Game.Update 호출을 막지만 일지·초대·수면 확인 패널은 시계를 막지 않는다. Schedule.Run은 (직전분, 현재분] 항목의 경로를 만든다. 로드와 기상은 현재 시각 목적지로 즉시 배치하고 이벤트 종료는 걸어서 복귀한다.

24시에는 종료하지 않는다. 26시가 되면 다음 평상 프레임에서 EndDay(PassedOut)으로 하루를 끝낸다. 침대 수면도 같은 EndDay를 사용한다. 이벤트 중 하루 종료는 거부한다.

저장·불러오기

EndDay만 플레이 저장을 쓴다. 완료·수락·취소·게임 종료는 저장하지 않는다. SaveFile은 tmp를 본 파일과 교체하며 이전 파일 하나를 bak로 남긴다. Read는 JSON 파싱 오류 때 bak를 읽지만 스키마/버전/체크섬/내용 불변식을 검증하지 않는다. 권한·디스크 오류는 호출자에게 전파된다. 로드한 Game은 NPC를 일정으로 재구성한다.

후속 시스템

방/마법/생활/관계 규칙은 후속 계약을 따른다. 현재 없는 명령·상태는 JSON만 추가해 활성화되지 않는다. 구체 Core 구현·Content DTO·GameState 기본값·프레임 연결·사전 검사·UI를 함께 추가해야 한다.

GameState에 영속 DTO를, Content에 정의 DTO를 더한다. 기능별 Core 클래스가 검증/계산을 맡고 Game이 실제 변경과 호출 순서를 정한다. 상태 변경은 같은 스레드에서 입력 한 건씩 처리한다. 범용 StateStore/revision/포트 계층을 요구하지 않는다. 실패 가능 검사를 먼저 수행한 뒤 구체 메서드에서 소비·산출·완료키를 묶어 쓴다. 새 도메인에서 부분 적용을 막는 단위는 그 메서드의 시험으로 검증한다.

현재 EventRun은 move/say/choice만 처리한다. 수업·방 목표 등 조작이 필요하면 해당 Task가 구체 실행 객체와 성공/취소 결과를 추가하고, EventRun이 그 완료를 기다리게 한다. 임의 메서드명 실행이나 eval은 금지한다. 새 명령과 효과는 구현·DTO·사전 검사와 함께 추가한다.

전경과 방

전경은 Game.Event 하나다. 실시간 방은 후속 RoomRun 하나를 Game에 추가한다. RoomRun이 활성일 때 방의 입력/적/투사체를 틱하고 전경 중에는 방 조작을 정지한다. 메뉴는 모든 게임 틱을 정지한다. 현재의 일지/초대 패널 시간 진행은 유지하며 새 패널의 정지 여부를 UI 구현 때 명시한다.

방 입장 체크포인트는 임시 상태다. reset은 현재 방 미확정 적·장치·전리품만 폐기한다. 이전 확정 증거·지갑·재배를 되돌리지 않는다. 전투/수동 장치 경로는 동일 outcome으로 합류하고 공통 수리에서 node.a3/증거/사건보상을 한 번 기록한다. eventId 완료 집합만으로 여러 경로의 공유 보상을 대신하지 않는다. 7-6에서 명시적인 공유 완료키 집합을 추가한다.

저장과 호환

플레이 저장은 수면/기절 EndDay에서만 한다. 성공 이벤트·거래·관계 수락은 그날 메모리에 남고 다음 하루 저장에서 영속한다. 강제 종료는 마지막 하루 저장으로 돌아간다. 방 체크포인트나 이벤트 시작 Actor 복사를 디스크 안전 세대로 부르지 않는다.

새 영속 필드는 기본값/로드 정규화/현재 무버전 저장 호환을 함께 구현한다. loan·RoomRun·전리품 preview·경로·대화·EventRun은 직렬화하지 않는다. 최종 실습의 별도 보관 파일은 12-1에서 추가할 명시적 예외이며 일반 자동 저장 정책을 바꾸지 않는다. 현재 SaveFile의 tmp/bak를 확장하고 필요할 때만 버전과 내용 검증을 추가한다.

시간과 귀환

Day와 Minute가 시간의 단일 원천이다. 계절=(Day%80)/20, 5일 패턴=Day%5로 파생하고 필요 시 순환 연도를 표시한다. 저장 필드에 중복 달력을 만들지 않는다. 하루 정산은 EndDay에서 끝난 날의 성장/돌봄 → Day 증가/시각 초기화 → 새날 자동 급수/재입고 → NPC 재배치 → 저장 순서로 확장한다. 실패 전 쓰기를 막고 동일 day 재정산을 차단한다.

24시 귀환은 폐기한다. 02시에는 새 방 행동을 막고 현 방 미확정 상태를 정리한 뒤 EndDay(PassedOut) 하나로 합류한다. 전경 이벤트 중 EndDay는 기존처럼 거부하고, 성공 비용으로 02시를 넘기면 종료 뒤 평상 프레임에서 처리한다. 수업 등 한 활동의 시간 비용은 한 소유자만 마지막 성공 때 가산한다.

플레이 규칙 보존

무료 공격·회피·도구와 무료 해결 경로, 선물0 관계, 기한 없는 약속, 사건 외부 자유 순서, 엔딩 후 생활을 유지한다. 지급 출처는 산출/회수에도 grant를 보존하고 loan은 과제 임시 상태에만 둔다. P07은 요리·연금 공용이며 fine 판매 배율1. 관계 R2는 R1 이후 서로 다른 참여 2유형이고 평생 첫 유형 +8 기록과 분리한다. 공격권은 min(교전 설정, 프리셋 설정, 전역3)이다.

재배 → 제작 → 설치 (후속 7-2/7-3/8-2)

끝난 날의 물준 기록으로 성장 → 다음날 초기화/자동 급수. 수확은 출처를 보존한다. Crafting은 재료·scope·공간을 먼저 검증하고 한 요청에서 소비/산출을 반영한다. Projects는 무료 대여 실험과 영구 설치 납품을 구분한다. loan 산출은 과제 밖에 반출·저장하지 않는다.

종료와 복구

2.3 계산식

구매

  • crowns ≥ price × qty를 확인한 뒤, 지갑 차감과 인벤토리 Add를 같은 원자 커밋으로 처리합니다.
  • 결과: normal 등급

판매

  • 판매 단가 = sellPrice × grade계수
  • grade계수: normal 1, granted 0, rental은 거부

판매 감쇠 [제] — 직접 채집·재배 대량 생산이 최적 전략이 되지 않게 합니다.

  • 일일 카테고리별 누적 판매액 S를 기준으로 판정합니다.
  • S < 200이면 100%, 200 이상이면 25%를 적용합니다.
  • 07:00 경계큐에서 S를 초기화합니다.
  • 화면에 "오늘 이 가게가 더 사기 어려워요"를 표시합니다. 판매 거부가 아니라 감액입니다.

환매 차익 없음

  • 같은 품목의 판매가는 구매가의 40%이므로, 사고팔기 반복으로 이익이 나지 않습니다.

2.4 로드 시 콘텐츠 검증 (실패 시 로드 거부) [제]

  • V1: 모든 레시피에서 sell(output) ≤ floor(0.9 × Σ minCost(slot))
  • minCost는 슬롯을 만족하는 품목 중 가장 싼 buyPrice입니다. 구매 불가 품목만 만족하면 refValue를 씁니다.
  • V2: 씨앗의 sellPrice는 0입니다. 씨앗 → 수확 → 씨앗 순환으로 돈을 만들지 못하게 합니다.
  • V3: granted·rental 생성 경로가 있는 품목은 예외 없이 0.1 표를 따라야 합니다.
  • V4: 실패 반환 범용 재료의 판매가는 레시피 최저 입력 1개의 판매가 이하여야 합니다.

2.5 경합·실패

  • 메인 조건에 구매를 요구하지 않습니다.

  • 시작 지급 재료로 만든 연금품을 팔려 하면: 판매 화면에 0크라운으로 표시되고 판매 버튼이 비활성화된다.

  • 같은 행동을 반복해도 새 항목은 열리지 않습니다.

먹이

  • 연금·요리 결과물을 씁니다. 원문의 '진정 향'은 생물 돌봄 용도입니다.

5.2 성질 사전 [원 4종 + 제 확장]

  • 확장 [제]: warm, cleanse, resonant, growth, fiber, sturdy, flavor

RecipeDef

  • outputItem, outputQty
  • timeCostMinutes
  • station
  • discoveryHint

원칙

  • 대체재 [원]: 슬롯은 기본적으로 성질이나 카테고리로 지정합니다. 그 성질을 가진 어떤 재료든 넣을 수 있습니다. requireItem은 서사상 필요한 예외에만 쓰며, 그 품목에는 구매처 또는 대여처가 반드시 있어야 합니다.
  • 성질 두 개 조합 [원]: 연금·요리 레시피의 식별 키는 (성질A, 성질B, process)이며 순서는 무관합니다.

5.6 일괄 제작 [원 P07]

한 프레임

GameRoot는 입력을 처리한다. 메뉴가 열려 있으면 Game.Update를 호출하지 않는다. 메뉴가 아니면 dt를 최대 0.1초로 제한하고 한 번 호출한다. 초대/일지/침대 확인 패널에서는 플레이어 입력만 0이며, NPC와 시계는 계속 간다.

Game.Update는 Event가 있으면 EventRun.Update만 실행하고 반환한다. 따라서 이벤트 중 평상 NPC 일정·일반 플레이어 이동·자연 시간은 정지하며 이벤트 이동과 대화는 진행한다. Event가 없으면 플레이어 이동 → NPC 경로 이동 → 초 누적을 게임분으로 전환 → Schedule.Run → 02:00 검사 순서다. 별도 완료 큐·revision·정지 채널·비동기 Handle은 없다.

권위 상태와 저장

GameState의 Day, Minute, Player, Wallet, Flags, Completed, Appointments가 영속 상태다. Player는 실제 Actor이고 UI Transform은 권위가 아니다. NPC Actor 목록은 Game이 가지며 저장하지 않는다. Path, Speed, Moving, EventRun, Dialogue, Hidden, 메뉴, 입력, 초 잔여량은 영속하지 않는다.

State는 가변 객체다. 완료 시 효과를 순차 적용하고 Completed에 eventId를 추가한 뒤 비용을 가산하고 약속을 제거한다. 현재 코드는 범용 원자 트랜잭션이나 예외 롤백을 보장하지 않는다. 유효한 콘텐츠를 사전 시험하는 전제이며, 새 효과는 검증 후 쓰는 구체적 메서드로 추가한다. 잘못된 효과 중간 예외가 부분 변경을 남길 가능성은 Task5의 확인 항목이다.

시간과 하루 종료

Day는 0부터, UI는 Day+1이다. Minute는 해당 생활일의 07:00=420에서 시작하고 자정을 지나도 1440 이상으로 이어진다. 02:00=1560에 기절한다. 자연 시간은 1초=1게임분이다. 이벤트의 CostMinutes는 성공할 때 한 번 더한다. 현재 이벤트 비용으로 1560을 넘겨도 다음 평상 Update에서 하루 종료를 검사한다.

침대 반경 1 이내의 수면 확인은 EndDay(Slept), 시간 초과는 EndDay(PassedOut)를 부른다. EndDay는 이벤트 중 거부한다. Day++ → Minute=420 → 초 잔여량=0 → 침대로 플레이어 배치 → 현재 일정으로 NPC 배치 → SaveFile.Write 순서다. 성공 이벤트·수락·취소·종료 자체는 저장하지 않는다. 그날 미저장 진행은 강제 종료/불러오기 때 마지막 하루 저장으로 돌아간다.

그래픽과 좌표

논리 1칸은 32×32 픽셀 타일이다. 좌표는 double, 셀은 floor(x), floor(y), 셀 중심은 +0.5, 월드 y는 위로 증가한다. 플레이어 속도는 초당 3칸, 충돌 반경은 0.2칸이다. 일반 이동은 축별 검사이며 sweep 충돌은 구현되지 않았다. NPC/이벤트 이동은 4방향 BFS와 경로 추종을 쓴다. 포털 셀에 새로 진입할 때만 전이한다.

현재 Stage5Art/runtime-manifest.json은 pixelsPerUnit=16이고 WorldView 기본값도 16이다. 이는 32×32 제작 기준과의 기존 불일치다. Task6-6/15-7에서 32px 원본·manifest·표시 검사를 함께 맞추며, 숫자만 바꾸어 자산 변환 완료로 보지 않는다.

이후 확장 원칙

새 규칙은 Core 안의 작은 구체 클래스/메서드, 데이터 정의는 Content, 영속 값은 GameState, 화면은 Game에 추가한다. Game이 호출 순서와 상태 변경을 통제한다. 공통 파일은 같은 단계라도 순서대로 수정한다. 분리된 규칙 파일과 시험만 독립 작업할 수 있다.

실시간 방은 Game.Event와 별도의 임시 RoomRun을 두는 후속 설계다. 한 프레임에서 전경 이벤트와 방 실시간 조작을 동시에 진행하지 않는다. 수면·기절은 RoomRun 정리 후 기존 EndDay 하나로 합류한다. 방 체크포인트는 세션 내 재시도용이며 디스크 자동 저장과 다르다.

후속 필드를 추가할 때 기본값, 로드 정규화, 구형 현재 저장 fixture 왕복을 함께 구현한다. 기존 v1/v2 전체 저장 예제는 이전 엔진 자료이며 현재 저장에 그대로 로드하거나 강제 보존하지 않는다. 버전·마이그레이션이 필요하면 현재 무버전 GameState를 최초 입력으로 지원한다.
