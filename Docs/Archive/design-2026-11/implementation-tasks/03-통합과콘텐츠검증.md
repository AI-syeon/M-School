# Task 10–18: 검증·전체 골격·콘텐츠 확장

2026-11-06 현 Core 기반 개정. 아래 작업은 미착수 계획이다. [현재 구조](구현구조.md)와 [확장 계약](../systems/full-design/02-contracts.md)을 따른다. 경로는 Assets/MagicCampus 기준이며 새 규칙은 Core, 입력/표시는 Game에 둔다. 전경은 EventRun 최대1, 상태는 GameState, 저장은 수면/02시 EndDay다. 공통 Content.cs/GameState.cs/Game.cs/Event.cs/GameRoot.cs 편집은 같은 단계에서도 순차 진행한다. 별도 규칙/시험 파일만 독립 수행할 수 있다.

새 명령/DTO/영속 필드는 해당 Task가 구현·기본값·로드 정규화·사전 검사·현재 저장 호환까지 함께 추가한다. perform/완료키/loan/방 상태 등은 현재 미구현 확장이며 기존 v2 스키마에 있다는 이유로 지원된 것으로 보지 않는다.

## 단계 10 — 핵심 체험의 병렬 검증

### Task 10-1 — 60–90분 사용자 체험 검증

- 현 기반 연결: 현재 GameRoot 빌드에서 수면/02시·하루 저장 안내까지 사용자 경험으로 확인한다. 일지 중 시간 진행과 미저장 하루 손실을 관찰 기록에 포함한다.

- 직접 선행: 9-1. 원본 §1·§12·§16과 기존 M5를 읽는다.
- 목적/소유: `Validation/CoreExperience/User/`의 절차·관찰·결과 보고서. 게임 소스와 공통 콘텐츠를 수정하지 않는다.
- 입력→출력: 고정된 체험 빌드/콘텐츠 해시·타깃8명 → 활동별 시간/행동/다음 계획·개선 후보.
- 처리 구조: 별도 설명 없이 플레이 → 새 주문 후10분 관찰 → 하루 관리 시간 분류 → 다음 할 일2개/만날 인물1명 질문.
- 경계: 양 경로는 전투/생활 선호에 따라 관찰한다. 60–90분 핵심 체험과 원본의 첫2시간 도입 검증을 구분한다.
- 저장/실패: 사용한 초기 프로필/지원 요청/포기 위치를 보존한다. 관찰자가 진행을 대신하면 해당 구간을 보조로 기록한다.
- 완료 조건: 6/8명의 자발적 계획/응용, 필수 반복20% 이하 목표와 실제값을 비교한다. 미달이어도 수치를 숨기지 않고 11-1 수정 입력으로 넘긴다.

### Task 10-2 — 시스템 경계·복구·양경로 통합 검증

- 현 기반 연결: 현재 Core와 실제 Player를 검사한다. Event1개·RoomRun·02시 정리·하루 저장·tmp/bak·공유 보상키를 재현하고 옛 임대/Handle 로그를 요구하지 않는다.

- 직접 선행: 9-1. [인수기준](인수기준.md) T02–T17·T19를 읽는다.
- 목적/소유: `Tests/Integration/CoreSystems/`, `Validation/CoreExperience/Technical/`. 사용자 관찰 데이터와 별도 영역이다.
- 입력→출력: 동일 고정 빌드·실패 프로필 → 재현 입력/trace/초기·결과 상태와 결함 목록.
- 처리 구조: 돈0·선물0·출석0·가방초과·NPC 경합·02시·전투3패·각 커밋 전후 종료를 조합한다. A3 두 경로 공통 수리/보상을 확인한다.
- 경계: 합격할 때까지 테스트 코드를 구현과 똑같이 바꾸지 않는다. 소유 모듈 수정은 11-1에서 진행한다.
- 저장/실패: 실행별 저장/해시를 분리하고 필수품 유실·부분소비·완료키 중복·임시 실행 상태 잔존를 검사한다.
- 완료 조건: 대표 회귀의 기대/실제/실패 위치가 모두 기록되고 진행 차단·데이터 손상 결함이 식별된다. 이후 장벽은 중대 결함0일 때만 닫는다.

## 단계 11 — 핵심 체험 수정 장벽

- 완료 조건: 기술 차단0·A01–A10 유지, 사용자 미달의 재검증 결과/남은 위험 명시. 이후 전체 콘텐츠 제작을 시작할 근거가 기록된다.

### Task 18-1 — 결함·분량 조정·회귀·최종 보고
