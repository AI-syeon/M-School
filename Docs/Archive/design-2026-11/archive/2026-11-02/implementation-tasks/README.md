# 매직캠퍼스 프로그래머 구현 계획

2026-11-02 · 시스템 기획을 구현 구조와 작업 단위로 전환 · **18단계 / 56개 Task / 전부 미착수**

원본 시스템 기획과 최신 함수 호출·실행·저장 계약을 읽고, 구현할 모듈과 데이터 흐름, 상태 소유권, 실패 복구, 검증 조건을 정리했다. 게임 코드는 작성하지 않았다. 향후 경로·타입·포트는 제안이며 현재 존재하는 게임 코드로 해석하지 않는다.

Claude의 기존 상세 시스템 원고를 근거로 사용했다. 이번 새 Claude CLI 요청은 DNS 오류로 응답을 받지 못했고, 제한 밖 재시도는 외부 전송 범위에 대한 자동 승인 검토에서 거부되었다. **현재 Task 분해·통합 검토의 작성자는 Codex이며, 새 Claude 작성·검토 완료를 주장하지 않는다.** 전송 승인 후 검토할 구체적 입력은 evidence에 준비되어 있다. [사용·검토 기록](Claude활용및검토.md)을 참고한다.

## 번호와 병렬 작업 규칙

`2-1`과 `2-2`는 같은 단계에서 독립적으로 수행할 수 있다. `3-1`은 **단계2 전체를 완료한 뒤** 수행한다. 직접 선행 목록은 해당 작업이 실제 사용하는 주요 산출물을 나타내며, 앞 단계 전체 완료 규칙과 함께 적용한다. 최대 병렬 개수는 권장 인력 수나 기간 추정이 아니다.

동일 단계의 작업은 서로 다른 파일·상태 소유 영역을 가진다. 공통 포트는 앞 단계에서 확정하고 단위 개발은 대역을 사용할 수 있다. 같은 단계의 다른 작업이 완성한 구현을 기다리지 않는다. 실제 배선·공통 등록·스키마 변경·공유 카탈로그 병합은 뒤의 단독 통합 작업에서 한다. 새 의존성이 생기면 번호를 다음 단계로 옮기고 이 표와 선행 목록을 함께 수정한다.

## 후속 구현 세션에서 사용하는 방법

예를 들어 `Task 2-1을 구현하라`는 요청을 받으면 공통 구현구조, 해당 카드, 1-1의 확정 계약, 최신 함수 문법/함수 사전/정상·부정 예제를 읽는다. 카드는 다음 정보를 모두 포함한다.

- 직접 선행과 읽을 원본/계약.
- 담당 모듈·향후 경로와 다른 작업의 수정 금지 경계.
- 입력/출력·알고리즘·상태 전이·소유권.
- 저장/실패/취소·복구 정책.
- 구현 후 확인할 객관적 완료 조건.

구현 결과는 수정 파일·검증 결과·미실행 범위·남은 문제를 기록한다. 모든 카드의 상태는 현재 미착수이며, 문서의 예시 경로를 만들었다는 이유만으로 완료하지 않는다. 소요기간/인원/최종 밸런스는 실제 기술 결정과 측정 전에는 확정하지 않는다.
