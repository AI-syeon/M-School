# Unity 구현 의존성과 단계별 완료 기준

이번 산출물은 시스템 설계다. 아래 단계는 앞으로 구현할 일이며 현재 통과한 Unity 시험으로 표시하지 않는다. 팀·기간·비용은 미확정이다.

| M1 첫 연결 이정표 | M0 | 2맵·문·목적지·이동/도착/취소, 최소 EventRunner(호출 칸 로더·함수 사전)·대화·effects 커밋·안전저장 | NPC와 이벤트 JSON만 추가해 지정장소 이동→실제 도착 뒤 대화→결과 저장→재로드. 아래 A01–10 모두 통과 |
| M2 일정·시간·복원 | M1 | 달력·정지 채널·예약합류·현재일정복귀·임대·async/await 핸들·호출 위치 진단 | 자정/겹친NPC/문실패/중간종료/디스크실패 인수사례. 핸들종결1·토큰누수0·보상중복0 |

## 첫 연결 이정표 A01–A10

| ID | 조작 | 객관적 완료 기준 |
|---|---|---|
| A01 | runner-bundle JSON을 로드 | 이벤트 이름으로 분기한 C# 없이 호출 칸을 함수 사전으로 파싱·해석. 잘못된 칸은 pointer·`event.x#n`·offset으로 거부 |
| A02 | 도입 완료 조건 false | 조건키·실제값 표시, 위치·완료·저장 변화0 |
| A03 | 초대 수락 | 전체임대·진입스냅샷 확보 뒤 이동 |
| A04 | 목적지 좌표만 유효한 다른 칸으로 수정 | 코드변경0, 같은 이동서비스로 새 위치 도착 |
| A05 | 도착 전에 대사 입력 | 대사 미표시, Handle Arrived 이후만 표시 |
| A06 | 두 선택지 각각 진행 | 해당 응답만, 효과 한 번 |
| A07 | 완료 저장→종료→로드 | 완료·시각·위치·보상 일치, 재지급0 |
| A08 | 이동·대사·선택 중 각각 종료 | 진입안전복원, Accepted 유지, 입력·토큰누수0 |
| A09 | 문닫힘/목표막힘/맵로드실패/취소2회 | 제한시간내종결1, 실패시 effects 커밋0, 마지막유효위치 |
| A10 | 새NPC/새이벤트/대사JSON추가 | 새전용스크립트없이A03–07통과 |

증거 묶음은 contentHash·saveVersion·UnityVersion·초기snapshot·입력순서·trace·결과snapshot이다. 동영상만으로 통과시키지 않는다. 문서검사와 게임실행/재미측정 결과는 다른 보고서로 둔다.

## 미정과 확정 방법

| 미정 | 권장안 | 언제·어떻게 결정 |
|---|---|---|
| Unity 버전·패키지·배포대상 | 지원중인 안정판 후보를 M0에서 비교, 현재 미채택 | 빌드/입력/저장 교체 시험 후 ADR |
| 기본 해상도·폰트·패드초점 | 16px타일·480×270은 출발점, 텍스트 별도 고해상도층 | M1 한국어200%·작은화면·패드가독성 |
| 충돌/속도·회피·적HP·주문효과 수치 | examples의 proposal 프로파일부터 시험 | M4 좁은문·8방향·읽기쉬운예고·두경로시간 |
| 각활동 게임분 비용 | 예제10/60분은 계약시험값, 실제과목별 별도결정 | M5 하루20–35분체감·시간부담검사 |
| 식물명11·부위산출·나머지레시피 | 예제프로파일, 원본이름확정아님 | M3 성질공급/손익/수확가독성 작성검토 |
| NPC대사·일정세부·36사건실제조작 | 원본목표와상태틀을유지 | M7 작가/기획자가힌트·대체도구까지검수 |
| 날씨·휴일세부 | 분위기/대사만, 필수진행조건금지 | M2 달력5일패턴 확정 |
| 실제40시간과재미 | 2402분예산, 필수서사630분, 메인12–18시간추정 | M8 12명이상 실측, 빈동선/반복부터조정 |

기획 변경 시 원본추적ID → 최종계약 → 스키마 → 정상·부정예제 → 인수사례 → 시각설명을 함께 갱신한다. 제작범위가 바뀌면 수량표와 시간예산도 동시에 수정한다.
