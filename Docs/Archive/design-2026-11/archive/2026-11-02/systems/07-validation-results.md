## 실제 수행한 검사

재현 명령: 프로젝트 루트에서 `node design/systems/tools/validate.cjs`. 전체 결과는 [report.json](validation/report.json)에 기록된다. 이 도구는 스키마에서 사용하는 키워드만 평가하는 문서용 검사기다. 호출 칸은 공용 파서 `tools/parse-calls.cjs`로 나누고 v1 함수 사전과 대조한다. 명령 실행이나 게임 상태 전이를 시뮬레이션하지 않는다.

## 작성 형식 개정(2026-11-02)

- 바꾼 것: 이벤트가 객체 명령 배열(명령 ID·move+await·parallel·commit·중첩 조건)에서 **Row 하나의 호출 칸**(trigger·when·script·forks·effects)으로 바뀌었다. interactions 표는 trigger 칸이, 일정 rows는 일정 script 칸이 대신한다. 규칙과 근거는 [함수 문법](full-design/11-function-syntax.md).
- 줄어든 크기: event.snack은 명령 객체 7개(이동 2·대사 1·선택 1·응답 2·커밋 1)에서 본문 호출 3개와 가지 호출 2개 + effects 1개로 줄었다. 이벤트 3개의 명령 호출은 본문 11개와 가지 4개다.
- 바꾸지 않은 것: 임대·핸들·원자 커밋(effects)·안전 스냅샷·저장 형식. 저장 payload 형식은 그대로이며(saveVersion 1) 번들 버전과 해시만 campus-demo.2로 갱신했다.
- 검증기 변경: 호출 문자열 파싱과 함수 사전 대조를 추가하고 핸들 규칙을 새 표기에 맞췄다. 이전 객체 형식(schemaVersion 1, commands·condition·once·interactions·rows)은 SCHEMA 오류로 거부한다.
- 검증기의 추가 규칙(11-function-syntax.md에 없는 것): 쓰이지 않는 가지(FORK_UNUSED)와 가지 순환(FORK_CYCLE)을 오류로 본다. v1 사전에는 `perform`과 도메인 조건·효과가 없어 UNKNOWN_FUNCTION이다.

## 명세 교차 검토와 수정

- 원본은 장면 중단 후 진입 안전 상태를 복원한다. 임의 호출 위치에서 재개하는 설계 대신 진입/완료 스냅샷으로 통일했다.
- 시간 정지를 calendar/ambient/player/worldSimulation으로 구분했다. 대화 정지 때문에 NPC의 장면 이동과 도착 대기가 영원히 끝나지 않는 충돌을 제거했다.
- 일반 이동·일정 이동·장면 이동을 같은 MoveService로 통합했다. 예약 합류만 명시적 숨김 준비 절차로 분리했다.
- 원본의 장면 우선순위는 대기 후보 선택에 적용하고 실행 중 장면은 유지한다. NPC/장소/UI/카메라의 전체 임대로 교착과 덮어쓰기를 막는다.
- 일정 이동은 취소·양도 가능한 제어권으로 구분했다. 전경 이벤트에는 전역 안전 저장 임대를 두어 한 장면 롤백이 동시에 완료한 다른 사건을 지우지 않게 했다. 동시 후보는 보존하고 장면 내부 연출은 async로 병렬 실행한다.
- JSON 표현 범위를 현재 스키마와 함수 사전에 구현된 함수와 향후 도메인 확장 계약으로 구분했다. 마법·전투·생활 시스템의 모든 규칙이 JSON만으로 이미 실행된다고 주장하지 않는다.
- Unity는 사용자 확정 사항으로 반영했다. 최신 요청에 따라 게임 프로젝트나 실행 코드를 구현하지 않았다.

## 남는 실제 검증

Unity 버전·패키지·배포 플랫폼은 아직 확정하지 않았다. 실제 충돌 sweep·재경로·문 로딩·예약 임대·대화 조작·파일 교체 중 강제 종료·마이그레이션·720 사건 순서 모델·60–90분 재미 검증은 실행하지 않았다. C#에서 같은 문법을 파싱하는 구현과 함수 사전 JSON(`schemas/functions.json`)은 아직 없다. 이 검증기의 함수 사전은 v1 범위 JS 객체다. [구현 계획](05-implementation.md)과 [검증 시나리오](06-verification.md)에 단계와 기대 결과를 명시했다. 현재 산출물의 완료는 **시스템 기획서와 일관된 예제·검증 자료의 작성 완료**이며 엔진/게임 구현 완료가 아니다.

원본 최종 Markdown 해시: `CAAACF9F4398FE7BBA5AFF54A777BDACCD29205C16C211DB57D44EB06CC8EDBA`. 기존 자료를 수정하지 않고 `design/systems`에만 추가했다.

## HTML 시각 자료 포함판

사용자의 추가 요청으로 `시스템_기획서.html`을 작성했다. 구조도·이벤트 7단계·맵 간 이동 경로·제어권 우선순위·시간 정지 표·저장 복구·구현 순서를 시각화했다. 시스템 본문 8개와 원본 콘텐츠 기획, 스키마·예제·보고서 JSON 6개를 파일에 포함한다. 외부 폰트·라이브러리·이미지 요청 없이 열 수 있다. 2026-11-02 개정으로 이벤트 7단계마다 해당 호출 위치와 문자열을 보여 주고, event.snack의 호출 분해 표를 추가했다.

`node design/systems/tools/build-guide.cjs`는 내부 링크·ID 중복·JavaScript 구문·표/제목 보존·외부 리소스 의존성을 검사한다. `node design/systems/tools/check-guide.cjs`는 문서용 모형 환경에서 이벤트 7단계와 단계별 호출 표시, 단계 호출이 실제 event.snack 호출 위치와 일치하는지, 선택 응답, 이전/다음, 정상/문 닫힘/목표 막힘, 두 저장 복구 상태, 전체 펼침/접힘, 내장 JSON 일치, 인쇄 시 펼침·원상복구, 내부 링크를 검사했다. 12개 검사 모두 통과했다. HTML 관련 결과는 `validation/html-report.json`과 `validation/html-interaction-report.json`에 기록했다.

실제 브라우저 렌더링은 확인하지 못했다. 내장 브라우저에서 로컬 미리보기 연결이 실패했고 로컬 파일 URL은 보안 정책으로 차단되었으며, Chrome 앱 접근은 승인되지 않았다. 제한을 우회하지 않고 파일 구조와 문서 전환 로직 검증을 수행했다. 호출 위치 줄과 호출 표의 줄바꿈·모바일 배치는 실제 화면에서 보지 못했다. 인쇄 스타일도 실제 인쇄 미리보기로 검증한 것으로 표시하지 않는다.
