01

플레이 규칙

플레이어는 배운 주문의 룬을 차례로 입력해 시전한다. 첫 실습에서는 어두운 안내판을 바라보고 Q → 1 → 2 → Enter를 눌러 등불을 켠다. 나중에 빠른 시전 기능을 해금하면 자주 쓰는 주문을 슬롯에 넣고 평소 필드에서 숫자 키 한 번으로 시전한다. 어떤 방식이든 시전하는 순간의 사용 조건과 대상을 확인한다.

제안 입력동작
자유 조작 중 Q영창을 열고 빈 입력 줄을 표시한다.
영창 중 1–4룬 하나를 추가한다. 주문마다 2–5개의 룬을 정한다. 같은 룬을 연달아 쓸 수 있다.
영창 중 Enter지금까지 입력한 배열과 정확히 일치하는 주문을 한 번 시도한다. 입력이 아직 짧으면 추가 입력을 안내한다.
영창 중 Q, Esc, X 또는 Backspace영창을 닫고 입력을 비운다. Esc를 다시 누르면 기존 메뉴가 열린다.
영창 밖 1–4해금 후 해당 슬롯의 주문을 즉시 시도한다. 빈 슬롯은 비어 있음을 표시한다.
  • 누르는 순간에만 룬 하나를 받는다. 여러 룬이 같은 프레임에 눌리거나 룬과 확정 키가 동시에 눌리면 그 프레임의 영창 입력을 무시하고 차례로 눌러 달라고 표시한다. GameRoot.Pressed로는 해당 키들의 입력 순서를 복원할 수 없다.
  • 입력한 배열로 시작하는 주문이 하나도 없으면 입력 줄을 비우고 영창을 열어 둔다. 입력이 비었거나 더 긴 주문의 앞부분에서 확정하면 영창을 유지한다. 정확히 일치하는 배열을 확정하면 성공 여부와 관계없이 영창을 닫고 결과를 HUD에 표시한다. 미습득 주문은 이름을 표시하지 않는다.
  • 초기안에는 룬 입력 제한 시간이 없다. 영창 중에도 이동과 세계 시간은 흐르므로 멈춰서 입력하거나 움직이며 조준할 수 있다. HUD는 입력한 룬, 확정 가능 여부, 취소 키를 글자와 기호로 표시한다.
  • 주문 수첩에는 배운 주문의 룬 배열과 사용 조건을 표시한다. 예를 들어 “집중 스탯 3 필요 · 현재 2” 또는 “실습용 렌즈 1개 필요 · 가방 0개”로 안내한다.

이 설계에서 영창 콤보는 키 입력으로 주문 하나를 지정하는 방법이다. 기존 마법 조합은 물결이 대상을 젖게 한 뒤 서리로 얼리는 식으로 시전된 주문들이 대상 상태에서 이어지는 규칙이다. Task 6-4의 보호 대상 검사, 등록 조합 우선, 단일 반응 순서를 사용한다. 기존 마법 반응 기획

02

현재 엔진의 연결 지점

현재 코드추가할 책임
GameRoot.cs · HandleKeys, Update, OnGUI키를 논리 룬이나 슬롯 번호로 바꾼다. 입력 문맥과 영창 HUD를 관리한다.
Game.cs · 단일 프레임, EventRun 최대 하나세션의 영창 상태를 들고 시전 요청을 받는다. 이벤트 중 요청을 막고 맵·하루가 바뀔 때 영창을 정리한다.
Content.cs · runner-bundle.json 로드SpellDef를 추가한다. Task 6-4의 주문 정의에 룬 배열, 조건, 빠른 슬롯 허용 여부를 둔다.
GameState.cs, SaveFile.cs배운 주문, 빠른 시전 해금, 슬롯 배치를 하루 저장에 포함한다.
Tests/Core/Program.cs · 번들 검사잘못된 정의를 출시 번들 검사에서 잡고, 시전과 저장을 Unity 없이 검증한다.

현재 플레이 빌드는 이동, 상호작용, 약속 이벤트와 하루 저장을 제공한다. 주문, 시전 대상, 인벤토리, 플레이어 스탯과 레벨은 새로 연결해야 한다. EventRun.Holds의 플래그 비교와 이벤트 보상은 약속 이벤트의 계약이다. 마법은 제안된 Core/Magic.cs에서 타입이 있는 조건과 결과를 다룬다. 현재 Core 기준 이벤트 실행기

두 입력 경로가 한 시전 규칙을 호출한다

설계안플레이와 구현의 차이
이동 중 키를 상시 수집하고 배열 완성 즉시 시전입력이 빠르다. 일반 조작을 주문으로 해석하지 않도록 키를 전용으로 비워야 하고, 짧은 배열이 긴 배열의 앞부분이면 기다리거나 데이터에서 금지해야 한다.
Q로 영창을 열고 Enter로 확정조작 의도를 명확히 구분한다. 1, 2와 1, 2, 3을 함께 쓸 수 있다. 영창이 익숙해진 뒤에는 해금한 슬롯으로 시작·확정 입력을 줄일 수 있다.

Core가 보관할 영창 상태는 열린 여부와 최대 5개의 룬이다. 배열 대조는 현재 주문 정의 목록으로 처리한다. 똑같은 배열은 잠긴 주문을 포함해 번들 전체에서 금지하고, 한 배열이 다른 배열의 앞부분인 경우는 허용한다. Magic.cs가 배열 대조와 조건 판정을 맡고, Game이 세션과 시전 호출을 연결한다.

Game.TryCastSpell은 설계상의 이름이다. 주문 ID와 현재 조준 정보로 호출한다. 키 종류, 영창 상태, 저장 슬롯 같은 입력 경로의 정보는 주문 효과 판정에서 사용하지 않는다.

  1. 현재 시전 가능한 문맥인지, 정의가 존재하고 주문을 배웠는지 확인한다.
  2. 현재 스탯·레벨·소지품 조건을 모두 확인한다. 수첩을 열었을 때의 판정 결과를 재사용하지 않는다.
  3. 현재 맵과 조준 정보에서 대상을 해석한다. 대상형은 사거리·허용 대상·보호 규칙을 검사한다. Task 6-4의 방출 규칙이 자원과 재사용 대기시간을 검사한다.
  4. 적용이 가능한 시전에만 효과와 비용을 확정한다. 생활 주문 비용은 0이다. 차후 전투 주문은 실제 방출 시 비용을 확정하고 빗나감은 명중 결과로 다룬다.

거부 결과에는 미습득, 조건 미달, 대상 없음, 보호 대상, 자원 부족 같은 코드와 표시용 인자를 담는다. 조건이나 유효성 검사에서 거부된 시도는 비용·재사용 대기·대상 상태·해금 상태를 바꾸지 않는다. 유효한 대상에 반응이 없을 때의 관찰 기록은 기존 Task 6-4 규칙을 따른다.

프레임마다 한 입력 문맥을 사용한다

  • F9가 우선한다. 메뉴, 패널, 대화 또는 Game.Event가 입력을 처리하는 동안 영창과 슬롯은 작동하지 않는다. 숫자 키로 대화 선택지를 고르는 기존 경로를 사용한다.
  • 자유 조작에서 패널을 여는 키와 마법 입력이 겹치면 패널이 우선한다. 영창을 여닫거나 확정한 프레임은 다른 마법 입력을 소비한다. 슬롯이 여러 개 동시에 눌려도 어느 슬롯도 시전하지 않는다.
  • 메뉴와 패널을 여는 경로는 키와 HUD 클릭에서 함께 호출하는 함수에 모은다. 이 함수, 포커스 상실, 이벤트 시작, 포털 통과, 방 재시도, 하루 종료와 F9에서 영창 입력을 지운다. 패널이 닫히거나 포커스가 돌아올 때 새 키 입력을 기다린다.
  • 현재처럼 입력을 받은 뒤 Game.Update에서 이동과 시계를 진행한다. 대상 미리보기와 시전 판정은 같은 대상 선택 규칙을 사용하고, 실제 시전은 입력 처리 시점의 위치와 방향으로 다시 확인한다. 같은 프레임의 이동으로 포털을 통과하거나 02시에 하루가 끝나면 남은 영창을 비운다.
  • Task 7-5의 수업 이벤트가 실습을 기다릴 때에는 해당 실습에 한해 연습할 주문과 대상을 지정한다. 이때도 공통 시전 규칙으로 실습 결과를 반환한다. 첫 습득 실습은 수업이 지정한 주문을 연습용으로 일시 허용하고, 정식 습득은 실습 성공 처리에서 기록한다.

03

사용 조건과 소유 데이터

주문 정의의 requirements는 조건 목록이다. 초기에는 모두 충족해야 하며 빈 목록은 추가 제한 없이 통과한다. 주문 습득 여부는 공통으로 확인한다. 아이템을 갖고 있어야 한다는 조건은 소지량을 읽는다. 차후 소모가 필요한 주문은 방출 비용으로 별도 정의한다.

조건 종류판정데이터가 생기는 지점
statAtLeast스탯 ID의 현재 값 ≥ 기준값해당 스탯을 소유한 성장 규칙의 조회를 사용한다. 집중력 같은 소모 자원은 방출 비용에서 처리한다.
levelAtLeast지정한 성장 항목의 레벨 ≥ 기준값레벨을 제공하는 성장 항목이 도입될 때 연결한다. 학교 전체 공통 레벨을 만들지 않고, 필요하면 학과·실습 숙련 등 실제 도입된 항목을 지정한다.
itemCountAtLeast지정 아이템의 사용 가능한 가방 수량 ≥ 기준값Task 6-2 인벤토리의 소지량 조회를 사용한다. 초기안은 가방의 normal·grant만 센다. 우편·보관함과 과제용 임시 loan은 제외한다.

아래는 스탯과 인벤토리 조회가 연결된 뒤 주문 정의에 추가할 필드의 예시다. 실제 출시 밸런스와 콘텐츠 ID는 별도다.

{
  "id": "spell.lantern",
  "incantation": ["rune1", "rune2"],
  "requirements": [
    { "kind": "statAtLeast", "id": "stat.focus_control", "min": 3 },
    { "kind": "itemCountAtLeast", "id": "item.practice_lens", "min": 1 }
  ],
  "allowQuickCast": true
}

번들 검사는 배열 길이와 룬 값, 주문 ID와 배열 중복, 조건 종류·기준값·참조 ID, 해당 조건을 읽을 수 있는지 확인한다. 기준값은 1 이상의 정수다. 제공자가 없는 조건을 포함한 출시 주문은 검사에서 거부한다. 지원되는 항목에서 저장 데이터가 누락된 경우에는 해당 시스템의 초기값을 사용한다. 첫 플레이 검증은 조건 없는 등불과 배운 주문 목록이 있는 전용 시작 픽스처로 가능하다. 수업에서 주문을 배우는 흐름은 Task 7-5에 연결한다. 성장 방향과 기존 슬롯 기획

04

빠른 시전 해금과 슬롯 편집

초기 제안은 한 번 성공하면 슬롯 편집 기능을 여는 자기 대상 주문이다. 이 주문을 배우고 영창으로 성공시키면 GameState.QuickCastUnlocked를 켠다. 같은 주문을 다시 써도 해금은 한 번이고 슬롯 배치는 보존한다. 해금 주문의 allowQuickCast는 false로 둔다.

  • 해금 후 교전과 이벤트 밖에서 주문 수첩을 열고 4개 슬롯에 배운 주문을 넣거나, 교체하거나, 비운다. 한 슬롯에는 주문 하나를 둔다. 배치할 때는 습득 여부와 빠른 시전 허용 여부를 검사한다. 가방 물품을 잠시 잃어도 슬롯은 유지하며 다음 시도에서 부족한 조건을 표시한다.
  • 슬롯은 주문 ID를 저장한다. 1–4는 기본 슬롯 호출 키다. 물리 키를 바꾸는 기능을 추가할 때는 조작 설정에서 키와 논리 슬롯을 매핑한다. 주문 배치와 별개로 예약 키 및 문맥별 충돌을 검사한다.
  • 영속 필드는 KnownSpells(빈 목록), QuickCastUnlocked(false), QuickSlots(빈 슬롯 4개)다. 실제 데이터 도입 시 현재 무버전 저장에서 누락·null을 기본값으로 정규화하고 슬롯 길이를 4로 맞춘다. 삭제된 주문 또는 슬롯에 쓸 수 없게 된 주문은 해당 슬롯을 비운다. 미해금 저장은 빈 슬롯으로 정규화한다.
  • 룬 입력, HUD 메시지, 현재 대상은 세션 데이터다. 해금과 슬롯 변경은 수면 또는 02시 EndDay에서 저장한다. 하루를 마치기 전 F9를 누르면 마지막 저장의 해금 및 배치 상태로 돌아간다. 현재 저장 계약

기존 상세 기획의 Q 홀드 주문 고리, 숫자로 슬롯 선택 후 우클릭 시전, 시작 슬롯에 등불·부유 배치는 이 제안과 충돌한다. 채택 시 Q는 영창, 숫자는 빠른 시전, 주문 수첩은 슬롯 편집에 배정한다. 전투 중 메뉴 정지와 패드 입력은 전투와 입력 설정을 붙일 때 확정한다. 배운 주문은 슬롯 밖에서도 영창으로 사용할 수 있다. 기존 조작과 슬롯 초안

05

구현 단위와 통과 기준

순서연결 범위통과 기준
1. 주문 입력과 등불Task 6-4 첫 단계. Core에 주문 정의·영창·공통 시전과 고정 대상 하나를 추가한다. Task 6-1의 방 대상이 준비되어 있으면 그 대상에 연결하고, 먼저 확인할 때는 전용 픽스처에만 단일 안내판을 둔다.Q → 1 → 2 → Enter로 사거리 안의 안내판을 한 번 밝힌다. 짧은 배열과 긴 배열의 공존, 중복 배열 거부, 잘못된 룬, 누르고 있기, 동시 입력, 대상 없음과 보호 대상을 확인한다.
2. 문맥과 실데이터 조건GameRoot 입력 우선순위와 HUD를 검증한다. Task 6-2 이후 소지 조건을, 수업 및 해당 성장 규칙이 준비되면 습득·스탯·레벨을 연결한다.대화 중 숫자는 선택에만 쓰인다. 메뉴 클릭, 포털, 포커스 상실, 이벤트, 02시, 재로드에서 영창이 사라진다. 각 조건의 기준값 직전과 정확히 같은 값을 검증한다. 입력 도중 아이템을 잃으면 시전 시 거부한다.
3. 빠른 시전해금 주문, 주문 수첩 편집, 슬롯 호출과 저장 호환을 연결한다. Task 6-5 수첩에서 주문과 조건을 표시한다.미해금 상태에선 슬롯이 작동하지 않는다. 해금 주문 재시전은 배치를 바꾸지 않는다. 같은 상태에서 영창과 슬롯은 같은 결과와 비용을 낸다. 오래된 저장의 기본값, 하루 종료 후 해금·배치 복구, 삭제된 주문 슬롯 정리를 검증한다.
4. 방과 전투 연동Task 6-4의 대상 반응을 Task 6-1의 방과 이후 전투에 연결한다.등록 마법 조합 6종의 방향과 우선순위는 입력 경로와 무관하다. 방 재시도 후 영창이 남지 않는다. 전투의 실제 방출 시 집중력이 한 번 차감된다.

Core 규칙은 dotnet run --project Tests/Core/MagicCampus.Core.Tests.csproj에서 확인한다. 기존 스위트는 이번 설계 시점의 워크스페이스에서 통과했다. 키 입력과 HUD 전환은 구현 후 Unity 플레이어에서 위 시나리오로 확인한다.

입력 수치와 키는 첫 플레이테스트 기본값이다. 빠른 시전은 기능 전체를 한 번에 여는 안으로 잡았다. 주문마다 무영창을 배우는 성장 방식으로 결정하면 해금 상태를 주문 ID 집합으로 바꾸고 슬롯 배치 검사를 그 집합에 연결한다. 두 방식 모두 같은 시전 규칙을 사용한다.
