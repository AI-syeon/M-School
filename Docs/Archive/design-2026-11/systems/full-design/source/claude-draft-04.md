# 4회 교차검토 결과

## 판정

**미완료(조건부).**

- 원본 17절의 범위, 공통 계약, 보정 결정의 방향은 대체로 일관됩니다.
- M1 경로(NPC·이벤트 JSON → 이동 → 대화 → 저장)는 지금 데이터로 착수할 수 있습니다.
- 그러나 사건 해결·최종·전투·마법 조합의 **상태를 쓰는 주체와 정의 데이터**가 빠져 있습니다. 또 예제가 채택 규칙과 모순됩니다. 이 상태로는 M4·M6 구현자가 규칙을 다시 발명해야 합니다.
- 아래 1–7을 수정한 뒤 재검증하면 완료로 판정할 수 있습니다.

## 우선순위 문제 12건

### 1. [치명] 사건 해결·진실·최종 상태를 쓰는 주체가 없음

- **위치:** `runner.schema` 효과 목록, `event.a3_*.commit`, catalog 최상위 배열
- **재현:** `event.a3_device`를 커밋하면 `node.a3` 완료와 150크라운만 기록됩니다. 다음 상태는 갱신되지 않습니다.
  - `flag.a_resolved`, `projection.a`
  - `questStates.resolved`, `caseResolutionOrder`
- **영향:** 이 상태들이 없으므로 `caseCountGte`, 진실 정리 A/B, H02·H03·H04 해금, 최종 준비가 발동하지 않습니다.
- **추가 누락:** 진실 A/B 장면, 최종 3구간, 친구·교직원 역할 판정, 엔딩 3종 projection, 도입 s1–s6의 정의 배열이 catalog에 없습니다.
- **필요 수정:**
  - "node3 완료 → 사건 해결" 파생 규칙을 `CaseService`의 소유 규칙으로 명시합니다.
  - 해결 순서 기록 시점을 정합니다.
  - `truth`, `final`, `ending`, `intro` 정의 스키마를 추가합니다.

### 2. [높음] 주요 사건 방과 교전 정의가 없음

- `room.case_a1`~`f3`는 symbols에만 있고 `rooms` 배열에 없습니다. 따라서 18노드 모두 다음 항목이 없습니다.
  - 힌트 3단계, 교직원 도움, reset 정책
  - 노드별 대여대, 안전 거점
  - 전투·장치 두 목표의 구성
- `perform(encounter)`의 `definitionId`가 `enemy.cleaner`입니다. 적 하나가 교전 정의를 대신하고 있습니다.
- `safe-save.defeats`의 `encounter.a3`는 정의되지 않은 참조입니다. 검증기가 이를 잡지 못합니다.
- **필요 수정:**
  - `encounters[]`를 추가합니다. 필드: 적 목록, `maxAttackers`, 장치 목표, 결과 키, 패배 카운트 키
  - 메인 방 18개 정의를 추가합니다.
  - 3패배 시 지원 부적(집중력 100 상한, 이미 100이면 +30 미누적)을 `rules`에 넣습니다.

### 3. [높음] 반응 데이터가 채택된 R1–R6 표와 모순됨

- **combo_4:** `spell.sprout`가 단독으로 `seed → opened_seed`를 냅니다.
  - 불씨 조합이 무의미해집니다.
  - "발아 준비" 선행 상태가 없습니다.
  - 살아 있는 작물 보호 태그도 없습니다.
- **combo_5:** `spell.illusion`이 단독으로 `record → projected`를 냅니다. 등불 광원 전제가 없습니다.
- **combo_6:** `requiresTag:"broken_stone"`과 `requiredTags:["shaped","repaired"]`가 이중으로 정의되어 있습니다.
  - 그런데 돌다듬기 후 태그가 `shaped`로 바뀌어 `spell.repair`(targetTag `broken`)가 대상을 잃습니다.
  - 결과적으로 순서 무관 규칙이 깨집니다.
- **combo_2:** `order:"tag-then-cast"`인데 `directionPolicy:"either"`입니다. 역방향(바람길 태그)이 없습니다.
- `windowSeconds:0`이 "무기한"인지 "무효"인지 정의되어 있지 않습니다.
- 역순 시전 시의 관찰 문장 키가 없습니다.
- **필요 수정:** 선행 태그, 촉발 주문, 역순 결과, 창 의미를 필드로 분리하고 단일 반응과 중복되지 않게 합니다.

### 4. [높음] 주문 템플릿이 1개로 축소됨

- `spells.template` 단일 필드뿐이어서 "비교전 대상형 + 교전 발사형·영역형"을 표현할 수 없습니다.
- 생활 시전 비용 0과 교전 비용 10–30의 구분도 규칙 텍스트에만 있습니다.
- **필요 수정:** `lifeTemplate`, `combatTemplate`, 교전 전용 지속시간과 상태 효과 필드를 둡니다.

### 5. [높음] 적 행동 원리를 실행 가능하게 표현할 수 없음

- 12종 모두 피해 12, 예고 1초, 사거리 4로 같습니다. 수치는 시험값으로 허용됩니다.
- 그러나 다음 규칙은 자유 텍스트(`counter`/`alternative`)뿐이고, 등록된 행동 키가 없습니다.
  - 과열 상태 피해 감소, 그림자 은폐 무효
  - 갑주 정면 90° 무효, 공명 구체 3고리와 메아리 초기화
  - 진정(Pacified)·정지(Disabled) 종료 조건
  - 분열체 토큰 공유
- **필요 수정:** `behaviorKeys`, `weaknessRules`, `resolutionOutcomes`를 C# 레지스트리 enum으로 정의합니다.

### 6. [높음] 큰 교전을 장면 이벤트로 감싸 계약과 충돌함

- `event.a3_combat`은 `pause:"none"`이면서 `input.player`와 `camera.main`을 장면 자원으로 임대합니다. 교전 결과도 이벤트 commit으로 확정합니다.
  - 이는 "교전은 방 활동, 전후 연출만 장면"이라는 계약에 어긋납니다.
- 자원도 저수로가 아니라 `space.map.courtyard`입니다.
- `category` enum에 general(100)과 schedule(10)이 없습니다. A3 연출은 interaction이 아니라 resolution(400)이어야 합니다.
- `once` const true 때문에 연습·복습·재방문 이벤트를 정의할 수 없습니다.

### 7. [높음] 난이도·접근성 값을 저장할 수 없음

- `settings.damageMultiplier`와 `telegraphMultiplier`가 integer입니다. 원본의 편안함 50%·150%를 담을 수 없습니다.
- 프리셋 필드가 없고, 조준 보조는 bool이라 강도를 표현하지 못합니다.
- **필요 수정:** number(또는 백분율 int)로 바꾸고 `preset` enum을 추가합니다.

### 8. [높음] 품질 fine에 도달할 수 없고, 판매 배율이 모순됨

- 보정 결과 식물에는 품질이 없습니다. 그런데 제작 품질 규칙(제 원고 2회)은 fine 입력을 전제합니다. 그래서 fine이 영원히 생성되지 않습니다.
- `recipes.qualityThreshold:2`의 의미가 정의되어 있지 않습니다.
- `04-data-contracts`는 fine 판매 배율 1.2, `09-adoption`은 1이라 서로 모순됩니다.
- **필요 수정:** fine 판정식을 정의합니다. 예: process 성공 조건 또는 시설 조건. 배율은 하나로 통일합니다.

### 9. [중] 저장 스키마의 상태 누락

다음 상태가 저장 스키마에 없습니다.
- 발견 레시피: "범위 미리보기"와 P07 일괄 제작의 전제
- 주문 응용 선택값
- 우편 종류와 초대→예약 연결
- 부탁 수락·연습 예약 상태
- `clue.preAccepted`
- 관계 사건의 invited 상태
- 동아리 모임 2의 선행(C01 → C02)도 데이터에 없습니다.

### 10. [중] 지급·대여 데이터가 빠지고 프로젝트 레시피 매핑이 틀림

- 수업·프로젝트 수락 시 1회 지급(원본 §6)을 담을 필드가 class와project 스키마에 없습니다.
- 부탁과 행사에는 대여 경로 필드가 없습니다.
- 프로젝트 레시피 매핑 오류:
  - P04(차 두 종류)가 `recipe.tool_4`(수선 공구)에 연결되어 있습니다.
  - P09–P12는 tool_1–4를 재사용합니다.

### 11. [중] 관계 집계 단위와 시간비용 출처가 이중

**관계 집계**
- 제 원고 3회는 콘텐츠 키당 +8, 통합본 V-relationships는 "첫 유형만 +8"(5유형)입니다.
- 둘 중 무엇인지 미결정이고, `r1BaselineActivityKeys`(키)와 "2유형"(유형)도 서로 맞지 않습니다.
- `activityType` enum에 행사와 동행이 없습니다.

**시간비용**
- `class.durationMinutes` 60과 `event.costMinutes` 10이 같은 수업에 공존합니다. 어느 값을 적용하는지 정해져 있지 않습니다.
- 초급 기초 수업에 "도입 완료" 선행 조건이 없고, `event.water_class`의 조건은 빈 all입니다. 그래서 도입 전에도 수강할 수 있습니다.

### 12. [중] 원본 요구 누락과 추적표 해상도 부족

- **원본 요구 누락:**
  - §5 "어떤 주문을 배우든 가까운 작은 문제를 수첩에 추가": 주문 습득 → 수첩·부탁 연결 필드가 없습니다.
  - §4 "공용 도구를 망가뜨리면 함께 고치는 후속 행동"도 없습니다.
- **추적표:** 343행이 모두 장(章) 단위 명세와 V-장 시나리오로만 연결됩니다. 따라서 "전 행 대응"을 증명하지 못합니다.
- **예제 데이터 오류(낮음):** 성질 순환 배정 때문에 "냉각제" = adhesive, "접착제" = cool로 원본 의미와 뒤바뀌어 있습니다.
