# 기반 교체 반영과 검토 항목

2026-11-06 개정은 Codex의 로컬 코드 대조로 작성했다. 새 Claude 검토를 수행했다는 뜻이 아니다. 이전 모델의 지적·수정 이력은 [보관본](../../archive/2026-11-02/systems/full-design/10-review-resolution.md)에 남긴다.

## 이번에 바로잡은 전제

서비스 포트/불변 Catalog/revision/Handle/임대를 현재 구현처럼 설명한 부분을 Core의 실제 메서드로 교체했다. 저장은 하루 종료만, 자정은 계속 진행하고 02시에 기절, 일정 복귀는 현시각 목적지로 걷는 흐름으로 통일했다. 현 함수 문법/저장 필드를 C#에서 다시 추출하고 56개 Task의 접점을 지정했다.

## 현 코드 제한과 후속 해결

| 제한 | 후속 책임 |
|---|---|
| 효과 예외 시 부분 쓰기 가능 | 새 도메인은 먼저 검증 후 쓰기, 5-1 위험 기록/9-1 회귀 |
| StartEvent가 Accepted를 내부 확인하지 않음 | 4-1 현재 동작 명시, 7-7/8-4의 공통 요청 경로에서 재검증 |
| 파서 이스케이프·타입 컴파일 없음 | 새 명령 도입 Task가 지원과 사전 검사를 함께 추가 |
| 파일 IO 실패 시 다음날 메모리와 디스크 불일치 가능 | 5-1 기록, 9-1 재시도/상태 표시, 13-2 장애 검증 |
| 무버전 저장·내용 검증 없음 | 최초 새 영속 DTO 추가 때 기본값/정규화, 필요 시 현재 저장 migration |
| 옛 fixture 생성기는 현 형식 미대응 | 4-4 재생성 주의, 9-1 현 DTO 대응 후 재현 생성 |
| Stage5Art 16px | 6-6/15-7에서 32×32 실제 자산 정합 |
| Unity 전체 회귀 미재실행 | 5-1 장벽을 문서만으로 합격 처리하지 않음 |

수업시간 단일 소유·P07 fine·R2 재참여·사건 공유 보상·loan 비영속 규칙은 새 구조에서도 유지한다. 정확한 구현 상태와 시험 결과는 [최신 검증](../07-validation-results.md)에만 기록한다.
