# 구현 후 확인할 인수 기준

이 문서는 시험 계획이다. 아래 항목은 현재 Unity에서 실행하거나 합격시킨 결과가 아니다. 기존 정적 검증 결과는 [기존 검증 보고서](../systems/full-design/06-validation.md)에 있다.

## 최소 연결의 진입 조건과 종료 조건

빈 프로젝트의 빌드, 순수 도메인의 Unity 의존 제거, 데이터 로드 오류 위치 표시가 먼저 가능해야 한다. 이후 두 맵·문·NPC·목적지·대화·선택·저장을 한 경로로 조립한다. 기존 M1의 A01–A10을 그대로 회귀 기준으로 사용한다.

| 기준 | 수행할 조작 | 종료를 인정할 증거 |
|---|---|---|
| A01 | 등록 함수 호출 칸으로 이벤트 로드 | 이벤트 이름별 코드 분기 없이 실행, 잘못된 칸은 pointer/호출/offset 표시 |
| A02 | 도입 완료 조건을 false로 설정 | 원인/실제값 표시, 위치·완료·저장 변화 0 |
| A03 | NPC 초대 수락 | 전체 임대와 진입 안전 상태가 이동보다 먼저 확보됨 |
| A04 | 목적지 JSON 좌표만 변경 | C# 변경 없이 공통 이동 서비스가 수정한 위치까지 도착 |
| A05 | 이동 중 대사 확인 입력 | 실제 도착 전 대사 표시 0 |
| A06 | 각 선택지를 별도로 실행 | 고른 가지의 응답만 표시, 효과 1회 |
| A07 | 성공 저장 후 종료·재로드 | 완료·시각·위치·보상 일치, 재지급 0 |
| A08 | 이동/대사/선택 중 종료 | 진입 안전 상태와 Accepted 예약 복원, 토큰/입력 잠금 누수 0 |
| A09 | 문 닫힘/목표 막힘/맵 실패/취소 중복 | 제한 시간 내 종결 1회, 실패 효과 0, 마지막 유효 위치 |
| A10 | NPC/이벤트/대사 JSON 추가 | 전용 스크립트 없이 A03–A07 재통과 |

최소 연결은 모든 도메인을 구현하기 전의 독립 장벽이다. 메모리 가짜 저장소만 사용한 검사는 A07–A09의 실제 디스크/맵 실패 검사를 대체하지 않는다.

720순열은 상태 전이의 검사다. 실제 대표 정순·역순·혼합 순서 플레이에서 길찾기·대사·관계/행사 경합도 확인한다. 최종 세 선택은 진행 조건을 추가하지 않는 표현 변형으로 검증한다.

## 사용자 검증 장벽

60–90분 핵심 체험에서는 8명 중 6명이 다음 할 일 2개와 만나고 싶은 인물 1명을 스스로 말하고, 수업 후 10분 안에 자발적으로 주문을 응용하는 것을 목표로 한다. 필수 반복 관리는 하루의 20% 이하를 목표로 측정한다. 첫 2시간은 12명 중 10명이 도입과 다음 행동 선택에 도달하는지 확인한다.

전체 콘텐츠 확장 후 12명 이상이 폭넓게 체험한 집단의 엔딩·주요 소진 시간 중앙값 36–44시간을 최초 목표로 한다. 2,402분의 기획 예산을 실제 플레이 시간으로 간주하지 않는다. 활동은 단일 버킷에 귀속하고 사건 내부 전투/이동·도입 수업 2개·관계 후속 준비·행사 재등장을 중복 집계하지 않는다.

## 결과 기록

Task별로 구현 버전, 콘텐츠 해시, 저장 버전, Unity 버전/플랫폼, 초기 안전 상태, 재현 입력, tick/sequence/revision trace, 최종 상태, 기대/실제, 통과/실패/미실행을 기록한다. 실패 원인과 수정한 Task를 연결하고 영향을 받는 항목만 회귀한다. 사용자 실측 결과에는 참여자 수·플레이 범위·활동별 시간을 함께 기록한다.
