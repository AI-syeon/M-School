# 매직캠퍼스 Unity 시스템 기획서 — 1회차

**범위:** 요구 분석, 누락 위험, 공통 계약(실행·시간·장면·예약·이동·저장), 캐릭터·입력·수업·마법·전투·탐험

**표기 규칙**
- **[원]** 원문 규칙
- **[계]** 이번에 채택한 공통 계약
- **[제]** 새 설계 제안. 프로토타입에서 검증할 권장 프로파일입니다.
- **[미]** 미정. 결정 주체와 시점이 필요합니다.
- 수치 중 [원]이 아닌 것은 모두 확정 사실이 아닙니다.

## 2. 공통 계약

### 2.1 실행 구조 [계]

**계층 구성**
- **도메인(C#):** 시간, 장면, 예약, 원장, 주문 판정, 전투 판정, 방 상태
- **콘텐츠(JSON):** 정의 데이터와, 등록된 조건·효과·명령의 조합
- **Unity 어댑터:** 표시, 입력, 충돌, 타일맵, 파일 I/O만 담당

**ID 규칙**
- 정의 ID는 `kind.name` 소문자 형식입니다. 예: `spell.ripple`, `lesson.ripple_basic`, `enemy.ink_blob`
- 원문 번호는 `source`에 둡니다. 예: `"M03"`
- 주문 영문명 매핑 **[제]**: lantern 등불, levitate 부유, ripple 물결, ember 불씨, sprout 싹틔움, stonecraft 돌다듬기, gust 돌풍, frost 서리, echo 메아리, mend 수선, illusion 환영, ward 결계

**JSON 제약**
- JSON이 미등록 조건·효과·명령 키를 쓰면 로드 단계에서 실패하고, 콘텐츠 ID와 경로를 보고합니다. 실행 중 무시하지 않습니다.
- 새 원리(예: 새로운 반응 판정)는 C# 도메인에 구현한 뒤 레지스트리에 등록합니다.

### 2.2 시간 [원]+[계]

**절대 시간**
- `absMinute:int64`는 게임 시작일 00:00 기준 누적 분입니다.
- 파생 값:
  - `day = absMinute / 1440`
  - `minuteOfDay = absMinute % 1440`
  - `weekday = day % 5` — 0·1·2 정규 수업일, 3 공동 실습일, 4 자유일 **[원 구성, 배정은 제]**
  - `season = (day % 80) / 20`
  - `semester = (day % 80) / 40`
  - `year = day / 80`
- 기상은 07:00입니다. 취침하면 다음 날 07:00으로 이동합니다. 07:00 이전 행동은 없습니다.

**시계 채널** — 각 채널은 독립된 정지 카운터(정지 요청자 집합)를 가집니다.

| 상황 | calendar | ambient | player | worldSimulation |
|---|---|---|---|---|
| 필드 이동·탐험·교전 | 진행 | 진행 | 진행 | 진행 |
| 대화, 메뉴, 수첩, 퍼즐 배치 화면 | 정지 | 진행 | 정지 | 정지 |
| 정식 수업·관계·행사 장면 | 정지 | 장면 소유 | 장면 입력 | 정지 (장면 소유 이동은 진행) |
| 전투 중 주문 고리, 일시정지 메뉴 | 정지 | 정지 | 정지 | 정지 |

**시간비용 커밋**
- 장면 완료 시 `timeCostMinutes`를 효과·보상과 같은 원자 커밋으로 더합니다.
- 중단·실패 시에는 더하지 않습니다.
- 커밋 결과가 24:00을 넘으면 24:00으로 고정하고, 커밋 직후 자정 절차를 실행합니다. 이미 기숙사에 있으면 취침만 제안합니다. **[제]**
- 장면 시작은 23:50까지 허용합니다. 이후에는 "내일 다시"로 예약을 이월합니다. **[제]**

**자정 절차 [원]**
1. 23:30에 귀환 알림을 띄웁니다. **[제 시각]**
2. 00:00이 되면 플레이어 상태에 따라 처리합니다.
   - 필드: 페이드 후 기숙사로 이동합니다.
   - 퍼즐 방: 방을 입장 상태로 복원한 뒤 이동합니다.
   - 교전 중: 선택지를 띄웁니다. 즉시 귀환하면 현재 방을 복원합니다. 교전 완료를 고르면 교전 종료 후 자동 귀환합니다.
3. 신규 교전 트리거를 비활성화합니다.
4. 퀘스트 물품과 확정 해금은 보존합니다. 현재 방 임시 전리품은 폐기합니다.

### 2.3 장면·임대·예약 [계]

**장면 정의 필드**
- `id`, `source`
- `category`: resolution / relationship / event / general / schedule
- `priority`: 400 / 300 / 200 / 100 / 10
- `location`
- `participants[]`
- `resources[]`: 배우·소품·지점
- `timeCostMinutes`
- `entryConditions[]`, `effects[]`, `rewards[]`
- `persistent:bool=true`

**처리 순서**
1. 후보를 수집합니다. 조건을 충족하고 장소가 일치하는 장면이 대상입니다.
2. 우선순위 내림차순으로 정렬합니다. 동률이면 등록 시각이 빠른 것, 그다음 ID 사전순입니다.
3. snapshot.world 전역 임대를 시도합니다. 실패하면 대기열에 남깁니다.
4. 자원 전체를 원자 임대합니다. 하나라도 실패하면 전체를 반환하고 다음 후보로 넘어갑니다.
5. 진입 안전 스냅샷을 만듭니다.
6. 실행합니다. 내부 연출만 parallel(all)을 허용합니다.
7. 성공 시 효과 + 보상원장 + 시간비용을 단일 커밋한 뒤 commit 스냅샷을 만듭니다.
8. 임대를 반환하고, 참가 NPC를 현재 시각 일정 위치로 복귀시킵니다.

**경합 규칙**
- 실행 중 장면은 선점하지 않습니다.
- 일정(10)은 더 높은 후보가 오면 취소 양도합니다.
- 진행 중인 교전·대화가 있으면 모든 후보가 대기합니다.

**예약**
- 필드: `reservationId`, `sceneId`, `location`, `windowStart/End(absMinute)`, `state`
- 상태 전이: pending → armed → running → done | expired
- 우편 수락 시 pending에서 armed로 바뀝니다.
- 플레이어가 장소에 진입하면 참가 NPC를 숨김 합류시킵니다. 이 처리는 예약 장면에만 허용합니다.
- `windowEnd`가 지나면 expired가 아니라 다음 날 같은 시간대로 자동 이월합니다. 원문의 "여러 날 찾게 하지 않음"에 따른 것입니다. **[제]**

**중단 처리**
- 장면 중간 종료 후 로드하면 진입 스냅샷에서 장면을 재시작합니다.
- 원장에 `sceneId`가 이미 있으면 보상을 다시 지급하지 않습니다.

### 2.4 이동 [계]

**좌표**
- 타일 좌표는 왼쪽 위가 원점이고 +y가 아래입니다. 1타일 = 16px **[원 시안 기준]**
- 엔티티는 `collisionRadius`(타일 단위 실수)를 가집니다. 목적지 도달 판정은 별도의 `arriveRadius`를 씁니다. 기본값: 플레이어 0.3/0.5, NPC 0.3/0.75 **[제]**

**경로 탐색**
- 맵 간: 방향성 문 그래프에 Dijkstra를 씁니다. 간선 비용은 맵 내부 추정 거리 + 문 통과 비용 1입니다.
- 맵 내부: 8방향 A*를 씁니다. 대각 이동 시 인접 두 직교 타일이 모두 통과 가능해야 합니다(모서리 끼기 금지).
- 실이동은 충돌 sweep으로 검증합니다.

**MoveHandle**
- 종결은 단 한 번입니다: Succeeded / Failed(reason) / Cancelled
- 타임아웃은 30 시뮬초입니다.
- 1초 정체 시 재탐색하며, 최대 3회입니다. **[제안값]**
- 실패 사유: NoPath, Timeout, Blocked, OwnerReleased

**속도·배치 [제]**
- 플레이어 5타일/초, NPC 4타일/초
- 생활권의 가장 먼 필수 장소까지 기본 이동 45초 이내 **[원]** → 경로 길이 225타일 이하로 배치를 검사합니다.

**정지 규칙**
- worldSimulation이 정지하면 일반 NPC MoveHandle은 일시정지합니다. 취소가 아닙니다.
- 장면 소유 이동은 계속 진행합니다.

### 2.5 저장 [계]+[제]

**저장 구성**
- `saveVersion`
- `clock.absMinute`
- `world`: 플래그, 완료 기록, 인벤토리, 위치
- `ledger`: `rewardKey` → `committedAt`
- `rooms`: `roomId` → {`confirmedFlags`, `openedDoors`}
- `reservations[]`
- `settings`
- MoveHandle과 임시 전리품은 저장하지 않습니다.

**저장 시점**
- 자동: 취침, 안전 거점 진입, 장면 commit
- 수동: 기숙사, 안전 거점
- 최종 실습 시작 전 별도 보관 슬롯 **[원]**

**로드 시 정합성 검사**
- 원장과 완료 플래그가 일치하지 않으면 원장을 우선합니다.
- 필수품은 수첩 저장소에서 복원합니다.

## 3. 캐릭터·입력

### 3.1 플레이어 [원]+[제]

**생성 항목**
- `displayName`: 1–10자 **[제]**
- `appearancePreset`
- `honorific`: 호칭

**상태 필드**

| 필드 | 기본값 |
|---|---|
| `hp` | 100 |
| `focus` | 100 **[원]** |
| `dodgeCooldown` | 1.0초 |
| `quickSlots[4]` | 시작 시 등불·부유 |
| `knownSpells` | — |
| `spellVariant[spellId]` | — |
| `situationLog[spellId]` | 집합 |
| `defeatCount[encounterId]` | — |

- HP와 집중력은 교전 종료 시 전부 회복합니다. 집중력은 **[원]**, HP는 **[제]**입니다.
- 비교전 상태에서 HP는 항상 최대입니다.

### 3.2 입력 행동 (논리 액션)

| 행동 | 키보드·마우스 [제] | 패드 [제] |
|---|---|---|
| Move | WASD (8방향) | 왼쪽 스틱 (8방향으로 양자화) |
| Interact | E | A |
| BasicBolt | 마우스 좌클릭 | X |
| Cast (현재 슬롯) | 마우스 우클릭 | Y |
| Slot1–4 | 1–4 | 십자키 |
| Dodge | Space | B |
| SpellRing | Q 홀드 | LB 홀드 |
| Notebook | Tab | View |
| Cancel/Pause | Esc | Menu |
| AimMode | 마우스 방향 자동 | 오른쪽 스틱 |

**조준 [원]+[제]**
- **비교전:** 사거리 3타일 안의 상호작용 가능 대상 중 점수가 가장 높은 대상을 선택합니다.
  - 점수 = 정면각 가중 0.6 + 거리 가중 0.4
  - 외곽선과 행동명을 표시합니다. 시전하면 대상형으로 판정합니다.
- **교전:** 마우스 방향 또는 오른쪽 스틱 방향을 씁니다. 보조 조준은 기본 15°(설정 0–30°) 원뿔 안에서 가장 가까운 적으로 보정합니다.
- **불가 대상:** 사람과 사유물은 대상 후보에서 제외합니다. 커서를 올리면 "할 수 없는 일" 이유를 표시합니다.

**슬롯 정책 [원]**
- 정답 주문을 장착하지 않았다고 귀환을 강요하지 않습니다. 고리에서 습득한 모든 주문을 즉시 교체할 수 있습니다.

## 5. 마법

### 5.1 시전 처리 순서 [원 원리]+[제 순서]

1. **선택:** 슬롯 주문과 템플릿을 결정합니다. 비교전은 대상형, 교전은 주문 정의의 전투 템플릿을 씁니다.
2. **비용:** 비교전은 0입니다 **[원]**. 교전은 `focus >= cost`를 검사하고, 부족하면 시전 불가 표시와 함께 기초 마력탄을 제안합니다.
3. **대상 허용:** 사람·사유물·`noMagic` 태그는 중단합니다. 비용을 차감하지 않습니다.
4. **조합 판정:** 대상의 현재 상태 + 이번 주문이 등록 조합(5.3)에 해당하는지 고정 순서로 첫 일치를 찾습니다.
5. **단일 반응:** 대상 태그 × 주문 반응표를 적용합니다.
6. **무반응:** 관찰 정보를 수첩에 기록합니다(예: "열에는 반응하지 않는다"). 재료는 손실되지 않습니다 **[원]**.
7. **상태 부여·지속시간 시작**, 그다음 상황 기록(5.4)을 남깁니다.

**대상 태그 [원 7종 + 제 확장]**
- 원문: wet, flammable, plant, broken, resonant, dark, mechanical
- 확장: overheated, frozen, liftable, floating, seed_dry, sound_source, shadow, illusion_screen, record

### 5.3 등록 조합 6종 [원 종류]+[제 순서·판정]

**판정 순서:** 한 시전이 여러 조합에 해당하면 아래 R1부터 순서대로 첫 일치 하나만 적용합니다. 조합이 단일 반응보다 우선합니다.

| ID | 선행 상태 → 촉발 주문 | 결과 | 역순일 때 |
|---|---|---|---|
| R1 물결+서리 | `wet` (물결) → 서리 | `frozen` 표면 20초 (보행 가능). 적: 빙결 1.5초 후 둔화 | 서리 먼저: "젖은 표면이 없다" 관찰 정보. 이후 물결은 단순 `wet` |

| R4 싹틔움+불씨 | `seed_dry` + 싹틔움 '발아 준비' → 불씨 | 껍질 개방 → 수확 가능. 살아 있는 `plant`에는 불씨가 항상 무효 (보호 규칙) | 불씨 먼저: 그을음 관찰 정보. 손실 없음 |
| R5 등불+환영 | 등불 광원 활성 + `record` → 환영 | 기록 장면 투사 (조사 단서 표시) | 환영 먼저: "빛이 부족해 흐릿하다" |
| R6 수선+돌다듬기 | '성형됨' ∧ '수선됨' 누적, **순서 무관**, 방 재설정 전까지 유지 | 구조물 복구 (영구 플래그로 승격) | 한쪽만 하면: "부품이 부족하다 / 결합이 없다" |

이 6종 외의 조합은 지원하지 않으며, 각 주문의 단일 반응만 적용합니다. **[원]**

### 5.4 주문 응용 해금 [원]

- `situationLog[spellId]`는 등록된 `situationTag`의 집합입니다. 예: `levitate.furniture`, `levitate.stage_prop`, `levitate.counterweight`, `levitate.combat_throw`
- 서로 다른 태그가 3개 이상이면 해당 주문의 응용 선택지가 열립니다.
- 같은 태그를 반복해도 진행 점수가 오르지 않습니다.
- 전투 태그도 인정하지만 필수는 아닙니다. 복습실 과제마다 고유 태그를 부여해 부족분을 보충할 수 있습니다.
- 응용 변경은 기숙사에서 무료입니다.

### 6.4 변형 4종 [원 후보]+[제 행동]

변형은 행동 1개를 추가하며, 윤곽 색과 변형 아이콘으로 표시합니다.

- **분열 덩굴** `enemy.thorn_vine_split`: HP 50%에서 소형 덩굴 2개(HP 15, 경 공격)를 생성합니다. 1회만 분열합니다.
- **연속 돌진 인형** `enemy.overheated_cleaner_chain`: 첫 돌진 후 0.6초 재예고를 거쳐 2차 돌진합니다. 냉각 상태에서는 연속 돌진이 불가합니다.
- **이동 공명 구체** `enemy.resonance_orb_mobile`: 고리 충전 중 초당 2타일 이동하고, 파동 순간에는 정지합니다.

### 6.5 패배·방 복구 [원]+[제]

**방 상태 필드**
- `RoomState{entrySnapshot, tempLoot[], confirmedFlags, encounterState}`
- 방 진입 시 `entrySnapshot`을 기록합니다.
- 방을 클리어하면 `tempLoot`를 확정 인벤토리로 이동하고 `confirmedFlags`를 저장합니다.

**패배 처리 (HP 0)**
1. 페이드 후 마지막 안전 거점으로 이동합니다.
2. 현재 방만 `entrySnapshot`으로 복원합니다. 적과 퍼즐이 다시 배치됩니다.
3. 현재 방의 `tempLoot`를 폐기합니다.
4. 이전 방 완료, 확정 단서, 열린 문, 돈, 가구는 유지합니다.

**반복 패배 지원**
- `defeatCount[encounterId]`가 3이 되면 지원 부적과 장치 해결 힌트를 제안합니다.
- 사용해도 보상·관계·엔딩 등급을 감점하지 않습니다.
- 재도전 시 설명과 컷신을 건너뛸 수 있습니다.

## 7. 탐험

### 7.1 데이터 [원 구조]+[제 필드]

**권역** `RegionDef{id, safePoints[], mainRoute[], optionalRooms[3]}`
- 4권역: `region.whisper_forest`, `region.waterway`, `region.observatory`, `region.underground_archive`

**방** `RoomDef{id, principleTag, rentalStationId, exits[], hintChain[3], staffHelpSteps[], estimatedMinutes}`

**규칙**
- 입구에 `estimatedMinutes`와 다음 안전 거점을 표시합니다. **[원]**
- 안전 거점에 처음 진입하면 귀환문을 등록합니다. 귀환문은 발견한 거점끼리만 연결합니다.
- 선택 조사실 X01–X12는 메인 필수 방과 `roomId`를 공유하지 않습니다. 로드 시 검사합니다.

### 7.2 방 진행 흐름

1. 입장하면 `entrySnapshot`을 기록하고, 필요 주문이 없을 때 대여대 위치를 즉시 안내합니다. **[원]**
2. 작은 문제로 원리를 익히고, 변형 문제로 적용합니다. **[원]**
3. 퍼즐 조작 화면에서는 calendar를 정지합니다.
4. 체류 180초가 지나면 힌트 1단계를 제안합니다. 3단계는 관찰 대상 → 성질 → 구체 행동입니다. 즉시 열람할 수 있으며 감점은 없습니다.
5. 마지막 단계 이후에는 "교직원 도움"으로 현재 방을 단계별로 동행 해결합니다. 사건을 자동 완료하지 않습니다.
6. "현재 방 초기화"는 단서를 유지한 채 퍼즐만 복원합니다.

**힌트 공유**
- 힌트 진행 상태 `hintIndex[roomId]`는 수첩과 NPC 질문이 공유합니다.

### 7.3 인수 예

1. 물결 미습득 상태로 A3에 진입하면, 입구 안내에 수동 펌프 대여대가 표시된다. 펌프로 수위를 맞추면 물결 사용 시와 같은 `waterLevel` 상태에 도달한다.
2. 23:59 교전 중에 자정이 되면 선택지가 뜬다. 교전 완료를 고른 뒤 쓰러지면 방이 복원되고 기숙사 07:00이 된다. 이때 앞 방의 확정 단서는 유지되고 이번 방 전리품은 없다.
3. 보상 커밋 직후 강제 종료하고 다시 로드하면 commit 스냅샷에서 재개하며 보상은 1회만 지급된다. 커밋 전에 종료하면 진입부터 재시작한다.
