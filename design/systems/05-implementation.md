# Unity 구현 계획과 완료 기준

이 문서는 다음 개발을 위한 계획이다. 사용자의 최신 지시는 **Unity 사용·지금은 시스템 기획만**이므로 아래 단계는 이번 작업에서 구현하지 않는다. 단계 종료는 시연 영상만이 아니라 재현 데이터·검사 결과·실패 원인 기록으로 판단한다. 팀/예산을 모르는 상태에서 주차나 인원 수를 확정하지 않는다.

## 첫 실행 이정표의 객관적 인수 기준

첫 이정표 범위는 대화 중심 최소 흐름(event.snack)과 동일 실행 규칙의 일반 이동 한 건이다. branch·async 병렬·대형 콘텐츠·전투는 M3 이후다.

| ID | 재현 절차 | 통과 조건 |
|---|---|---|
| A01 | Unity에서 제공 JSON을 외부 콘텐츠로 로드 | 하드코딩된 event.snack 분기 없이 카탈로그에서 해석 |
| A02 | bool 초기값을 false로 변경 후 발동 시도 | CONDITION_FALSE와 키/현재값 확인, NPC 위치·저장 변경 없음 |
| A03 | 도입 완료 프로필로 초대 수락 | 진입 안전 저장·전체 임대 확보 후 이동 시작 |
| A04 | dest.snack 좌표를 유효한 다른 칸으로 변경 | C# 수정 없이 해당 위치로 경로 이동. radius 이내에서만 move 호출 완료 |
| A05 | 도착 전에 대사 확인 | 대사창 미표시. 실제 Arrived 이후만 표시 |
| A06 | 두 선택지를 각기 실행 | 선택한 응답만1회, 마지막 동일 memory.snack_done=true |
| A07 | 완료 후 저장·종료·재실행 | 위치·시각430·완료·기억 동일, 중복 시간/보상0 |
| A08 | 이동 중/대사 중/선택 직후 저장·종료 | 진입 안전 상태 복원, 완료 미기록, 초대 유지, 재진행 가능 |
| A09 | 길 막힘 또는 이동 취소 | 제한시간 내 실패/취소, effects 커밋0회, 임대·입력·카메라 누수0 |
| A10 | 새 NPC와 새 목적지/이벤트를 JSON으로 추가 | Unity 코드 변경 없이 A03–A07 통과, 이름·대사·행동 데이터만 추가 |

각 시험은 시작 snapshot·번들 해시·Unity 버전·입력 순서·결과 snapshot·trace를 함께 보관한다. 정상·실패·취소마다 handle 종결 수와 활성 임대 수를 검사한다. A10은 서린을 복제한 전용 스크립트가 아니라 새 ID 데이터만으로 실행해야 통과다.

## 책임 분리와 진행 중 결정

M0에서 플랫폼의 저장 파일 교체 방식을 시험하고 버전별 API를 선택한다. M1에서 실제 충돌 반경/재탐색 값을 튜닝한다. M2에서 저장 중 강제 종료를 실제 실행한다. M3에서 관찰 밖 NPC 논리 이동과 카메라 맵 표시 정책을 확인한다. M4에서 전체 게임 도메인 schema와 조건 연산을 확장한다. 이 결정 때문에 현재 문서의 최소 계약을 기능 목록으로 되돌리지 않는다.

기획 변경은 원본 요구 ID→계약→스키마→예제→검증 시나리오 순으로 영향 기록을 남긴다. 특정 콘텐츠가 새 명령을 요구하면 공통 동작인지 먼저 판단하고, 이미 있는 move/say/choice의 전용 변형을 콘텐츠 이름으로 추가하지 않는다. 새 함수가 필요하면 함수 사전·구현·정상례·부정례와 실패·취소·저장 계약을 함께 정의한다.
