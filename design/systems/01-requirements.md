# 원본 요구사항과 공통 시스템 대응

## 근거와 판정 기준

S는 [최종 콘텐츠 기획안](../마법학교_최초기획안.md)의 절 번호다. C는 [일관성 규칙](../플레이_일관성_규칙.md), Q는 [검토 기준](../검토기준.md), V는 [기존 검토 결과](../검토결과.md)다. 충돌 시 S가 C보다 우선한다. 여기서 **요구**는 원본 기획에 명시되어 이번 설계가 준수할 규칙이라는 뜻이며, 상용 게임에서 검증된 사실이라는 뜻은 아니다. **제안**은 이 문서가 구체화한 구현 규칙, **미정**은 구현 전에 결정하거나 시험할 값이다. ID는 이 문서 내부의 추적 키다.

## 요구를 실행 계약으로 바꾼 제안

| 결정 | 권장안 | 이유·영향 |
|---|---|---|
| D01 제안 | 단일 권위 상태 저장소, 효과만 영속 값 변경 | 이벤트·전투·대화의 직접 변경을 막고 저장·진단 재사용 |
| D02 제안 | 명시적 안전 체크포인트로 복원, 호출 위치(PC) 재개는 v1 제외 | 원본의 장면 진입 전 복원 규칙과 일치, 연출 복구 복잡도 절감 |
| D03 제안 | 장면 자원 전체를 시작 시 원자 임대, 우선순위는 대기열 선택에 적용 | 실행 중 높은 장면이 강제 끼어들지 않으며 교착 예방 |
| D04 제안 | 맵 내부 A*, 맵 간 출입구 Dijkstra, 8방향 모서리 끼기 금지 | 목표점만 주는 제작 경험과 진단 가능성 |
| D05 제안 | 인게임 시간과 독립된 시뮬레이션 틱, 정지 종류 분리 | 대화 중 달력은 멈추되 장면 NPC 이동은 계속해야 함 |
| D06 제안 | JSON은 닫힌 함수 사전(명령·조건·효과)을 호출 문자열로 쓰고, 미등록 함수는 로드 오류 | 오타·조용한 무시 방지, 지원 범위 명확화 |
| D07 제안 | 예약 합류는 숨겨진 안전 합류에서만 위치 보정 | 예약 보장과 눈앞 순간이동 방지; 일반 길찾기 실패와 구분 |

## 미결정 항목과 권장 결정 시점

| 항목 | 지금의 권장 가정 | 확정 방법·기한 |
|---|---|---|
| Unity 버전·패키지·배포 대상 | Unity 엔진은 사용자 확정, 언어는 C# 권장, 도메인 계약 유지 | M0에서 Unity 버전·패키지·대상 플랫폼을 ADR로 고정. 이번 작업은 시스템 기획만 수행 |
| 충돌 반경·속도·지도 크기 | 반경 0.25타일, 기본 3타일/시뮬초, 타일16px | M1 좁은 문·대각선 시험. 값 변경은 데이터 버전 관리 |
| 재경로 수치 | 무진행 1초 후 재탐색, 최대3회, 기본 이동 제한30시뮬초 | M1 밀집 NPC 테스트 후 조정 |
| 하루·주 표시 | 절대일0을 첫날, day%5로 5일 주기, 80일 순환 | S4의 주5일과 휴일 언급만으로 휴일 배치 불명확. M3에서 정규수업3/실습1/자유1로 우선 구현, 별도 휴일 여부 콘텐츠 확정 |
| 각 활동의 표시 시간 비용 | 이벤트가 costMinutes 명시, 예제는10분 | 콘텐츠 작성 단계에서 활동별 확정. 정지 실시간을 이중 가산하지 않음 |
| 대용량/스트리밍 월드 | 두 맵 시험은 전부 로드, 서비스는 논리 맵 ID 사용 | M2에서 관찰 밖 NPC·맵 로드 정책 시험 |
| 저장 파일 교체·손상 대응 | 동일 파일시스템 임시파일+이전 정상본 백업 | M2에서 실제 대상 플랫폼의 교체/중단 동작 검증 |
| 전투·연금·꾸미기 상세 조작 | 공통 상태·조건·효과·방 리셋만 이번 명세에 포함 | M4 도메인 명세 추가. 원본의 레시피/적 숫자를 JSON 지원 완료로 오인하지 않음 |

원본에 없는 프레임 처리·취소 결과·교착 처리·파일 형식은 모두 설계 제안이다. 가칭 N01 서린/N03 미라를 예제에 썼으며 R01 등의 실제 콘텐츠 전체를 제작했다고 주장하지 않는다.
